## Что известно и что ещё проверять

Требования источников: карточка — один элемент VoiceOver с `accessibilityActions`; роторы «ждут человека», «инциденты», «дорожки»; drag карточек дублируется меню, проекты — «Показать на доске» / «Скрыть с доски», LaneHeader — «Убрать с доски» и сдвиг. План §5 ограничивает объявления переходами в `waiting_human` и инцидентами. Reduce Transparency требует проверки деградации `glassEffect`, но результат этой проверки в источнике не утверждён.

Предлагаемые ниже требования к фокусу, исключению повторных объявлений и процедуре QA — дополнение team2 для реализации. Они не описывают найденные runtime-баги. В репозитории есть core-модули и spikes/frontend; полноценных экранов M3, на которых можно подтвердить этот план, пока нет. Проверку на macOS выполняет владелец на согласованной тестовой сессии; этот документ не требует сейчас менять личные настройки или запускать агента.

Контраст, размеры/раскладки элементов, тёмные темы и дизайн маскотов полностью исключены человеком. Аудит макетов не проводился. Reduce Motion упомянут в исходном §5, но отдельная работа по анимациям и маскотам в этот остаток T15 не входит.

## VoiceOver и клавиатура

У каждого интерактивного действия должна быть текстовая подпись из каталога F4; не произносить имя SF Symbol или технический commandId. Пользовательские названия проектов/стадий и id задач произносить как данные. Декоративные элементы внутри карточки не должны создавать дополнительные остановки поверх единого элемента карточки. Образец из плана §5: «SHOP-42, Dev, ждёт человека: лимит возвратов, возвраты 3 из 3» — пример, окончательная схема подстановок требует согласования.

|---|---|---|---|

Команда не вызывает оптимистичный переход | план §3.4, §3 Drag-and-drop; UC-11; арх. §2 |
| VO-03 Запрещённая цель | Карточка без критериев, read-only цель возврата, более поздняя стадия | Недопустимое действие недоступно; точная подпись объяснения, если отсутствует в источнике, остаётся «нет текста» до согласования. | VO-07 Роторы | Видимые/скрытые проекты, waiting_human разных стадий, инцидент | Роторы по §5 доступны. Предложение: ротор карточек охватывает видимую доску; скрытый проект доступен в сайдбаре со значком, переход к нему явно показывает дорожку. Семантику перехода согласовать | план §5; UC-15.6/8 |
| VO-08 Лист и панель | Пробел на карточке; Human Review; ReturnSheet; закрыть лист/панель | Доступны поля, «Куда», кнопки и подсказки; фокус не попадает на недоступные действия. Предложение: при закрытии вернуть фокус на исходную карточку, если она ещё существует | план §3.5/§3.7, §5 |
| VO-09 Автор коммитов | Первый отказ без identity; отказ с явным identity; params пустые | Общий текст и ошибки доступны для чтения; фокус в первое поле missing/invalid («Имя», затем «Почта»). | VO-10 Ошибки пайплайна | ValidationIssue error/warning, path/stageId, неизвестный код, params пустые | Текст, тип сообщения и связь с полем/стадией доступны VoiceOver; предупреждение не выключает «Сохранить»; без связи проверка недоступна и сохранение выключено согласно предложению плана | план §3.8; спека §4.1 |
| VO-11 Подозрительные файлы | agent/gate/merge, пустой/непустой комментарий; stale_suspicious_files | Пути/правило/размер/blob доступны; VoiceOver различает «Принять файлы и вернуть» и «Вернуть с замечанием». «Отправлено…» и обновление набора доступны без ложного объявления принятия | план §3.5; UC-25 |
| VO-12 Лог и менюбар | ⌘F в логе, загрузка ранее; MenuBarExtra и ждущая задача | Поиск/лог и «Открыть доску» доступны; предложение: обновление лога не уводит фокус, фоновая квота не перебивает речь | план §3.5/§3.12, §5 |

Матрица должна проверяться отдельно VoiceOver и клавиатурой: успешный drag мышью не доказывает доступность альтернативы. Фактический прогон режимов запланирован на будущую тестовую сессию M3; текущая работа ограничивается документом.

### Объявления и обновления проекции

- Источник состояния — TaskCard/события проекции, не текст ленты и не локальные догадки. Объявлять только waiting_human и инцидент согласно §5; не каждую секунду таймера, report_progress, WIP или процент квоты.
- Предложение: один свежий переход — одно объявление; `taskUpdated` + предметное событие одной транзакции не дают два объявления. После reconnect/resync текущий снимок не считать набором новых переходов. Неизвестное событие не рождает ложного изменения статуса.
- Предложение: сохранять фокус по id карточки/дорожки при обновлении модели и замене снимка. Если карточка исчезла или проект скрыли — использовать ближайшую доступную цель, без фокуса на удалённом элементе. Одинаковые названия разных проектов различать контекстом проекта, не маскотом.
- Тексты отдельного живого объявления, результата перестановки и недопустимого переноса: **нет текста** в источнике. Сначала согласовать их с Frontend/Analyst и добавить ключи, затем реализовать.

## Reduce Transparency

Здесь проверяется сохранение содержимого и работы интерфейса при уменьшенной прозрачности. Подбор цветов, измерение контраста, стресс раскладки и макеты не входят в работу.

| RT | Поверхность из плана | План проверки | Критерий приёмки |
|---|---|---|---|
| RT-01 | Хром окна/шапки, StageColumnHeader, LaneHeader | В согласованной macOS-сессии сравнить режимы без/с Reduce Transparency | Статусы, подписи и действия доступны; переход режима не пересоздаёт доску и не теряет фокус |
| RT-02 | TaskInspector | Открыть задачу, изменить режим в тестовой сессии | Вкладки/содержимое/поле ответа сохранены; выбранная задача и введённый текст не сбрасываются |
| RT-03 | ReturnSheet / настройки / поповер | Открытый лист с выбранной стадией и комментарием | Семантика «принимает/не принимает» и состояние кнопок не меняются; фон не скрывает содержимое |
| RT-04 | MenuBarExtra | Открыть список ждущих задач | Все исходные действия и значения сохраняются; событие не создаёт повторные объявления |
| RT-05 | glassEffect fallback | Зафиксировать фактическое поведение в spike на целевой macOS | Если системная деградация не обеспечивает доступность, Frontend выбирает поддерживаемый механизм; визуальные токены передать владельцу Designer отдельным вопросом, здесь не придумывать |

Какой fallback использовать и какие API/модификаторы поддерживает выбранная версия SDK, проверить в реализации на целевом Mac. Этот документ не заявляет, что `glassEffect` уже автоматически соблюдает все критерии. Изменение личных настроек текущего Mac и фактический прогон не выполнялись.

## Локализация: интеграция каталога F4

Полный инвентарь текстов — [frontend-strings-ru.md](frontend-strings-ru.md), задача F-T2-4 (отдельная ветка `team2/frontend-f4-russian-strings`, коммит `392e95e`; относительная ссылка станет доступна после включения F4 в main). T15 не создаёт второй словарь. Предложение: импортировать согласованные строки в String Catalog на этапе M3; сейчас создаётся только документ, без нового target или изменения Package.swift.

| Группа ключей | Правило будущей реализации | Проверка |
|---|---|---|
| board/card/inspector | Идентификатор ключа не зависит от отображаемого русского текста; общий ключ только при одинаковом смысле действия | «Перезапустить» и «Повторить», отмена и закрытие листа не случайно объединены; повторные подписи F4 проверены по контексту |
| Динамические значения | Сохранять пользовательские имена/id/пути как данные; не переводить их или git argv. Примеры «N стадий», «12 из 12» не превращать автоматически в утверждённый шаблон | Имена стадий из демона; даты/время/числа подставлены согласно согласованному шаблону; UI-примеры не зашиты как реальные значения |
| Число/длительность | Предложение: согласовать правила русских форм количества для стадий/дней/попыток; не создавать строку конкатенацией переведённых слов | 0, 1, 2, 5, 11, 21; формат длительности §4.1 s/m/h, неизвестные форматы — как есть; длинные строки проверять семантически, без аудита раскладки |
| validation.* | Все 37 кодов из спеки §4.1; stage из stageId, path из ValidationIssue.path, остальные из params | Один отсутствующий ключ → message целиком; неизвестный код → message + код; severity не выводится из кода |
| validation.duplicate_id / no_return_target | Первый ветвится по path, второй по наличию stageId | Возврат в returns_to и повтор id стадии не получают одинаковую фразу; уровень пайплайна не показывает ложную стадию |

| identity.* | Строки ошибок из UC-01 и поля params; отдельные ключи первого и повторного отказа | Правильный текст для missing/invalid; повторный ввод сохраняется; params пустые → общий текст |
| Accessibility | Те же точные названия действий, отдельные согласованные шаблоны описаний/объявлений | Нет произнесения ключей локализации, code/rawValue вместо подписи или перевода имени пользователя |
| Пустые/незаданные тексты | «нет текста» в документе — маркер пробела, не production-подпись | Отсутствующий текст согласован до реализации; ничего не выдумано и не отправлено в UI |

Ключи `textNNN` в F4 — временные предложения; перед импортом закрепить смысловые имена и не менять ключ при редактуре перевода. Источник каждого перевода сохранить в комментарии каталога: версия/раздел, назначение, параметры, примеры и ветви. Английский перевод, второй язык и новая политика locale не запрошены; это открытые продуктовые решения. План §3.5 явно задаёт время истории принятых файлов по Калининграду: не менять на системный часовой пояс без решения команды.
