## Дополнительные пробелы

- §4.1 одновременно перечисляет точные диапазоны и заканчивается «Диапазоны спека не фиксирует». Тип: неоднозначность, UC-13. Предложение: диапазоны таблицы считать справочными для текущего валидатора, значения для UI всегда брать из params; подтвердить, являются ли они проверяемым контрактом или только примерами.
- UC-21 говорит о свежести 60 с/30 мин и запасе на запущенные run, но не задаёт порядок резервирования при двух одновременных стартах. Тип: пробел, UC-03/21. Предложение: описать атомарную проверку/резерв в планировщике; кто выигрывает при одинаковом приоритете? Это M4, не требование готовой реализации M1.
- UC-25: stale-набор «ничего не принимается»; критерии старой v0.1 всё ещё говорят, что любой возврат принимает набор, хотя requestChanges с замечанием теперь не принимает. Дельту критериев ведёт AN2, здесь лишь ссылка на изменившееся правило.
- Крайний случай старого демона без params описан однозначно: fallback message; неизвестные коды также предусмотрены. Не объявлено пробелом.
- Лимит размера max_file_mb задаёт «МБ», но §4.1 не определяет десятичные/двоичные единицы. Тип: термин без определения, UC-25. Для ровно граничного файла требуется уточнение единиц; предложение определить число байт на МБ и правило строгого превышения.

### Откуда берутся подстановки

- `stage` — lookup по `stageId`, `path` — поле issue; это не обязательные ключи params. Нельзя требовать params.stage/path и на этом основании объявлять дефект.
- `yaml_syntax.line` — PipelineValidator.swift:73; path документированно пустой. Требование B2 «всегда непустой path» имеет это исключение.
- `n` — parser version и validator queue/merge count; `id` — duplicate/unknown stage/return target; `value` — parser invalid enum/duration и validator пустого git-правила.
- `key,line` — неизвестный YAML-ключ (PipelineParser.swift:258); `key` — env (PipelineValidator.swift:398).
- `field,kind` — field_not_allowed_for_kind, причём для wip это warning. Severity проверяется по полю issue, а не по справочному списку кодов.
- `harness` и `name` — validateAgent (unsupported harness, MCP allowlist); `when` — parser git-условия; `cmd` — первое слово неизвестной/пишущей read-only команды.
- `min,max` и опциональный `label` — range() (PipelineValidator.swift:101–105); для stall > wall max равен заданному wall; backoff_too_long.max — количество пауз, не длительность.
- `limit_out_of_range` для max_file_mb имеет только label и намеренный fallback message без min/max. Это совпадает с явным исключением §4.1.
- Для duplicate_id и no_return_target UI выбирает вариант текста по path/stageId; одна строка таблицы не означает один шаблон без контекста.
- Необходимые params в просмотренных producer-ветках соответствуют текстам; отсутствующий ключ у старого демона не блокирует UI: CommandErrorText/ValidationIssueText возвращают message. Перевод label и длительностей — слой UI, а не ответственность Codable.
