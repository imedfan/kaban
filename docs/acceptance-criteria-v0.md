# Kaban MVP: критерии приёмки (v0.1)

Автор: Kaban Analyst Bot. Основа: спека v0.8.1 и архитектура v0.11.1. Здесь только **проверяемые** условия. Поведение описано в спеке, тут не дублируется.

Вехи (план CEO): **M1** ядро на Linux (модель, автомат, хранилище, планировщик, фейковый драйвер); **M2** исполнение через настоящий `cursor-agent` (клоны, MCP доски, обёртка git, гейты); **M3** UI целиком; **M4** слияние, квоты и лимиты Cursor на реальных фикстурах; **M5** подпись и нотаризация.

Для M1 у каждого критерия есть исполняемый сценарий в `code/Scenarios/M1/` (формат описан в `code/Scenarios/README.md`). M1 принят, когда все сценарии M1 зелёные в `swift test` на Linux. Для M2–M5 сценарии пишу по ходу, на реальных фикстурах спайков.

## Сквозные инварианты (M1, генеративные тесты бэка)
- У задачи всегда ровно одна стадия и одно состояние из архитектуры 3.2. Причина есть только у `queued` (необязательная), `retry_wait`, `waiting_human`, `blocked`.
- Занятые WIP-слоты стадии = число задач в `running` + `gating` + `retry_wait`, и оно не больше WIP. Исключение: WIP уменьшили ниже текущего числа задач, тогда новых не берём.
- Сумма идущих run по всем проектам не больше общего потолка, а по проекту не больше его личного максимума.
- `attempt` в пределах 1…3 и сбрасывается в 1 при каждом входе в стадию. `autoRuns` в пределах 0…12 и обнуляется любым действием человека.
- Run с причиной `rate_limit`, `runner_auth`, `daemon_restart`, `silent_exit` или `model_substituted` не меняет ни `attempt`, ни `autoRuns`.
- Флаг планировщика никогда не убивает идущий run. Убивают только пауза задачи, перенос назад, отмена, 5 отказов git и подмена модели.
- Любое изменение состояния даёт журнальное событие с монотонным `seq`, а повтор журнала с нуля даёт тот же снимок.

|---|---|---|---|
| UC-01 Подключить проект | Не git → ошибка, проект не создан. Шаблон коммитит только `.kaban/`. После подключения флаг `pipeline_invalid` со списком стадий без модели. После указания моделей флаг снят, задачи стартуют. | M2 (валидатор M1) | M1-PIPE-01, M1-PIPE-02 |
| UC-02 Завести задачу | Новая задача `queued` в Backlog. Без критериев приёмки не стартует. Правка запрещена в `running` и `gating`. | M1 | — (добавлю M1-TASK-01) |
| UC-03 Автозапуск | Стартует только при свободном слоте, без флагов Мака, пула, проекта и модели. Порядок: возвращённые и отвеченные раньше новых, затем приоритет, затем FIFO. Задача, которая не может стартовать по причине, не держит очередь. | M1 | M1-FLOW-01, M1-WIP-01, M1-MODELFLAG-01, M1-POOL-01 |
| UC-04 Пройти стадию | `complete_stage` → `gating` → при зелёных гейтах `queued` в следующей стадии с `attempt` 1. Красный гейт → `retry_wait: gate_failed` в том же клоне. Read-only стадия с изменениями → откат и повтор, при повторном нарушении `invalid_result`. | M1 (гейты M2) | M1-FLOW-01, M1-RETRY-03 |
| UC-05 Возврат | `return_to_stage` в пределах лимита → `queued` в целевой стадии, счётчик пары +1. Превышен лимит пары (3 / 2) или общий (5) → `bounce_limit`, задача остаётся в своей стадии. | M1 | M1-RETRY-02, M1-BOUNCE-01, M1-BOUNCE-02 |
| UC-06 Агент просит человека | `request_human` → `waiting_human: question`, слот свободен. Ответ → `queued` в своей стадии с приоритетом, `autoRuns` = 0. Ожидающих без ревью ≥ `max_waiting_human` → флаг `intake_paused`. Замечание при исчерпанных попытках добавляет одну попытку. | M1 | M1-WIP-02, M1-MAXWH-01 |
| UC-07 Ревью человеком | В human-стадии `waiting_human: review`, не считается в `max_waiting_human`. «Одобрить» → очередь Merge. «Вернуть» → выбранная стадия, лимиты возвратов не растут. «Отклонить» → `cancelled` с `kaban/archive/<id>` или без него, либо стадия. | M1 | M1-MAXWH-01, M1-CANCEL-01 |
| UC-08 Слияние | Слияния по одной на проект, в порядке одобрения. Конфликт → первая agent-стадия, `conflict` +1, лимит 2 → `conflict_limit`, после возврата обязательно Human Review. Грязный `main` → `blocked: main_dirty` и флаг `merge_blocked`. | M4 | — |
| UC-09 Лимиты Cursor | Rate-limit: флаг Мака, cooldown 15 → 30 → 60, ручное снятие. Пул известен → флаг пула, встают только стадии этого пула. Пул неизвестен → флаг Мака. Модель недоступна → `queued: model_flag` только на её стадиях, проба не чаще раза в 10 мин. | M1 (распознавание M4) | M1-RATE-01, M1-NOCHARGE-*, M1-POOL-01, M1-POOL-02, M1-MODELFLAG-01, M1-SILENT-01 |
| UC-10 Сбой агента | 3 попытки, паузы 30 с и 2 мин, затем `retries_exhausted`. После краша и зависания `refs/kaban/wip/<run>` и откат клона, после `gate_failed` и `no_final_call` клон сохраняется. 13-й автозапуск → `run_limit`. Любое действие человека обнуляет `autoRuns`. | M1 | M1-RETRY-01, M1-RETRY-03, M1-WIP-03, M1-RUNLIMIT-01, M1-RUNLIMIT-02 |
| UC-11 Ручное управление | Пауза задачи убивает run без списания попытки, `paused` → `queued` при продолжении. Пауза Мака или проекта не убивает идущие run. Перенос вперёд через гейты запрещён. Отмена удаляет клон, ветка сохраняется по галочке. | M1 | M1-PAUSE-01, M1-MACPAUSE-01, M1-CANCEL-01 |
| UC-12 Перезапуск демона | Осиротевшие run → `retry_wait: daemon_restart` без списания. `gating` перезапускает гейты. Грязные клоны → `refs/kaban/wip`. Клиент дочитывает по `seq` или берёт снимок после `resyncRequired`. | M1 (процессы M2) | M1-NOCHARGE-daemon_restart (добавлю M1-RESTART-01 на повтор журнала) |
| UC-13 Изменить пайплайн | Невалидная версия не применяется. Удалить стадию с нетерминальными задачами нельзя. Уменьшение WIP никого не прерывает. Смена модели, гейтов и политики действует со следующего run. | M1 | M1-PIPE-02 (добавлю M1-PIPE-03…05) |
| UC-14 Несколько проектов | Слоты по кругу с весами, личный максимум соблюдается. Rate-limit общий, `max_waiting_human` и очередь слияния свои у каждого проекта. Папка пропала → флаг `project_missing`. | M1 | M1-FAIR-01 |
| UC-15 Проекты на доске | Перетаскивание и пункт меню добавляют дорожку, крестик скрывает, задачи скрытого проекта работают. Значок `waiting_human` или инцидента скрытого проекта виден в сайдбаре. Набор и порядок дорожек переживают перезапуск, при первом запуске на доске все проекты. ⌘1–⌘9, ⌘⌥←/→ работают. | M3 | — |
| UC-16 Маскот | Маскот стабилен по id проекта, меняется вручную, состояние отражает очередь. | M3 | — |
| UC-17 Запрещённая git-команда | Отказ сразу, с причиной, событие `gitDenied`. 5 отказов за run → `git_denials`. «Разрешить один раз» доставляется в ответе MCP или в следующем промпте и сгорает при `done` или `cancelled`. | M1 (обёртка M2) | M1-GIT-01 |
| UC-18 Инцидент | Нарушение инварианта → `waiting_human: incident`, событие `incidentOpened`, задача сама не продолжается, не входит в лимиты. | M2 | — |

| UC-21 Квота перед стартом | Опция выключена по умолчанию, без согласия не включается. Данные старше 60 с перед стартом обновляются, старше 30 мин считаются «нет данных». Порог 10% с запасом 2% на идущий run → `queued: quota_cm/om`. `nil` или `enabled: false` ≠ 0%. | M4 | — |

Повтор, перенос, возврат, отклонение и отмена принимают набор, `answerHuman` не принимает. Изменённый blob срабатывает снова. | M1 (git-diff M2) | M1-SUSP-01…05 |

## Нефункциональные (M3–M5), мои предложения, в спеке их пока нет
- Доска с 5 проектами по 50 задач держит 60 fps при прокрутке и перетаскивании на `mbp` (M3).
- После перезапуска демона UI восстанавливает состояние меньше чем за 2 с без потери событий (M3).
- Приложение и демон подписаны и нотаризованы, LaunchAgent ставится без ручных шагов, кроме разрешений macOS (M5).
