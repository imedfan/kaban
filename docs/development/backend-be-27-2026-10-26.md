# BE-27: compiled git shim в PATH run

26 октября 2026. Реализация `0051a22`, ветка `codex/be-27-git-shim`.
`git fetch origin` выполнен; исходная база `origin/main` — `27f83d4`.
Зависимость BE-26 `cccf843` из [PR #121](https://github.com/imedfan/kaban/pull/121)
включена в эту ветку. Основной checkout с незакоммиченной BE-31 не изменялся.

## Реализовано

- Swift executable `KabanGitShim`: отдельный product/target SwiftPM и native
  target Xcode, `Contents/MacOS/KabanGitShim` рядом с `KabanDaemon`.
  CodeSignOnCopy, идентификатор `app.kaban.git-shim`, Hardened Runtime,
  без App Sandbox. Signing checker проверяет все три подписи.
- На каждый run штатного host создаётся `git-bin/git` внутри изолированного
  HOME, symlink на executable shim. Этот каталог первый в PATH перед
  сохранённым toolchain PATH BE-23. Пропавший shim блокирует сборку env:
  прямого fallback на настоящий git нет.
- Env содержит `KABAN_GIT_CHECK_URL`, `KABAN_RUN_TOKEN` и абсолютный
  `KABAN_GIT_BIN=/usr/bin/git`. Подтверждённый `ProjectSummary.identity`
  задаёт author/committer env: изолированный HOME не содержит gitconfig
  пользователя. Реальный commit проверен вместе с его автором.
- Перед exec отправляются точные argv и cwd с bearer token. Только HTTP 200
  с JSON boolean `allow: true` разрешает execv; stdin, streams, cwd и exit
  status настоящего git сохраняются. Нет Python/bash fallback в production.
- Только loopback URL `/git/check`, без redirects; HTTP/resource timeout 2 с.
  Неответивший daemon, malformed JSON, HTTP error или отсутствующее env
  дают ненулевой выход и дословный текст UC-17 «…или дождись разрешения».
- Политика, grants, счётчик отказов и journal остаются в серверном коде BE-12/26.
  Интеграция compiled shim подтверждает отказ, gitDenied, allowGitOnce,
  одно потребление и waiting_human: git_denials после пяти отказов.
- Старые тесты script wrapper теперь запускают собранный executable.
  HTTP fake в host-suite дожидается завершения своих конечных запросов перед
  следующим scheduler pass: stop effect не обрывает проверяемый replay.
  Fresh-recheck проверяет config первого dev run, учитывая допустимый старт
  следующей стадии в том же pass.

  (29 Transport, 70 Protocol, 183 Kit, 215 DaemonCore, 223 BoardCore).

  Для обоих bundles signing checker подтвердил три identifier, runtime и
  отсутствие Sandbox; Mach-O contents checker подтвердил QA/production состав.
- Тот же executable smoke из Debug и Release bundles — passed.
- Два host integration tests повторены с `KABAN_DAEMON`/`KABAN_GIT_SHIM`,
  указывающими на Release bundle: настоящий commit и host restart/401 — passed.
- Настоящий Debug WindowGroup `--ui-smoke` — passed: typed create/edit/move/

  LaunchAgent не выполнялась.
- `tools/smoke-daemon-transport.py --bin-dir .build/debug` — passed.
- `python3 tools/check-project-context.py`, `git diff --check` — passed.

Первые focused прогоны нашли отсутствие git author в отдельном HOME и гонки
фикстуры final HTTP replay/следующей стадии; причины устранены, assertions
на успешный commit, автора и duplicate HTTP responses сохранены.
Локальный Linux-прогон не выполнялся; проверки executable добавлены в оба CI jobs.
Первый Linux CI на `e9afebc` успешно собрал shim, затем обнаружил отсутствие
`/usr/bin/curl` в контейнере Swift 6.1: HTTP fake BE-26 не мог отправить ни одного
финального вызова. В Linux setup добавлен curl; тестовые assertions не ослаблялись.
Это зависимость тестового HTTP-агента, production shim curl не использует.

## Ревью

Проверены diff, callers сборки env, preflight/spawn, server grant transaction,
нормализация argv, связанные signing/package/CI consumers. Wire DTO и SQLite
миграции не меняются. Токен не попадает в argv, URL, сообщения отказа или файлы
shim; redirect не пересылает его. Критичных проблем в изменённом коде не найдено.
Оставшиеся границы ниже относятся к live и файловой изоляции.

## Границы

Live Cursor не запускался. `cursor-agent -p`, installed LaunchAgent/reboot,
Seatbelt и полный M1/MVP этой проверкой не подтверждены. Фейковый HTTP-агент
делает настоящий git commit на стандартном пресете; живой критерий BE-27
остаётся открытым до BE-22/BE-24.

В `research/` нет результатов спайка 1, подтверждающих формат CLI deny rules.
По условию задачи правила не генерируются по предположению. Существующий
список `GitCheck.cursorDenyRules` сохранён; настраиваемые запреты остаются
на `/git/check`, чтобы одноразовый grant мог пройти через shim. Подключение
подтверждённого формата жёстких правил остаётся за live-интеграцией BE-22/24.

Прямой `/usr/bin/git` обходит PATH shim по принятой архитектуре §8.2;
файловая защита — BE-28, проверка результата — существующая BE-13.
Diagnostic passes без attached MCP host сохраняют прежнее окружение.
Прежняя script/install API KabanKit была внутренней: все её потребители
в репозитории обновлены; wire DTO, schema и legacy decoding не менялись.
