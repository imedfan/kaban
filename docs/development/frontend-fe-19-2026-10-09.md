## Поведение

Раздел «Инциденты» читает durable `listIncidents(projectIds: nil, state: all)`.
Open/all фильтрует показанную историю. Скрытие проекта с доски не скрывает его
инциденты. Глобальный и проектный count приходят из BoardProjection/ProjectSummary;
число прочитанных строк не становится aggregate.

В записи видны проект, задача, kind, run, время, сообщённые объекты отката и
выбранное действие. Удалённые проект/задача сохраняют readable историю.
Неизвестный kind сохраняет исходную строку; отсутствующий лог имеет отдельную
диагностику. При ошибке чтения/offline последняя история остаётся доступна,
решение отключено до актуального чтения.

Возврат с замечанием привязан к record/card/frozen pipeline. Доступны текущий
writable agent и предшествующие writable agents по on_success. Default берётся
из producer; незаполненные legacy факты не заменяются current project pipeline.
Stale draft требует явного принятия актуальных данных и сохраняет замечание.
Command journal переживает reopen; `.ok` оставляет pending до correlated events.
Общее поле answer и общий move/retry menu не обходят incident decision.
Отмена использует существующую confirmation TaskControlSheet.

Изменение модели не разрешает инцидент. «Ужесточить политику» открывает общий
validated draft сразу в Git-разделе; его открытие не меняет состояние.
Hard invariants остаются обязательными. Optional resolution metadata сохраняет
command/target/keepBranch/commandId вместе с resolvedAt, journal и project count.
История действия читается после discardJournal. keepBranch означает выбор
человека; внешний archive/delete не объявляется завершённым по DB receipt.

`IncidentKind` сохраняет scalar wire format и unknown значения; обязательные
поля остались строгими. `TaskDetail.incidentPipeline`, `Incident.resolution` и
`IncidentResolved.resolution` optional для legacy DTO.

Unknown-kind regression сначала воспроизвёл DecodingError. Core проверки
покрывают late read, reconnect/replacement, stopped reader, сохранение cache при
ошибке, hidden/deleted history, строгие required fields и отсутствие локального
пересчёта count. Decision tests проверяют exact target/comment, stale context,
`.ok` без resolution, идемпотентный replay того же commandId и durable draft.
Реальные IncidentTests проверяют refs/tags/config/foreign rollback, отмену,
model change без resume и metadata после retention/reopen.

Native script запускает настоящее WindowGroup с bundled stdio daemon и private
БД/Git в `/tmp`. Известные нарушения создаются настоящими Git изменениями;
rollback выполняет production store. Отдельно после rollback одна private
serialized запись получает future kind, чтобы проверить неизвестный wire DTO.
Это имитация будущего producer, а не обнаружение нового реального нарушения.

Проверены empty, refs, tags, config, foreign base, длинная .kaban запись,
unknown kind, deleted history и её log sheet, hidden project, missing log, disconnected cache,
policy draft, model removal без resume, retention, return через native menu и
reopen history после второго discardJournal. Light/dark, 1040×640 minimum,
длинный текст и прокрутка к return action сняты. Просмотрены refs, empty,
unknown, hidden/deleted history, deleted/missing log, policy, long controls,
return и reopen frames. Native menu
валидирует Cmd-Return route и выполняет тот же action; это не физическое нажатие.
Каждый процесс завершает developer transport; script проверяет освобождение
настоящей writer lease перед следующим запуском, без retry успешности.

[Checks](screenshots/fe-19/checks.json) и [manifest](screenshots/fe-19/frames.json)
фиксируют source revision, SHA-256 и размеры каждого кадра.

## Границы

Проверен developer private stdio. Installed XPC/helper registration, physical
pointer/keys и VoiceOver остаются для FE-22. Cursor CLI, платные prompt runs и
системная регистрация не использовались. Изменение модели проверено снятием
реального task override; живой каталог Cursor для новой модели этим не доказан.
Policy route проверен без применения нового YAML; сохранение validated policy
покрыто FE-15. Backend не сообщает before/after SHA для каждого rollback объекта;
UI показывает его реальные rolledBack значения и не придумывает эти hashes.

Review выполнено автором последовательно по diff, lifetime, event ordering и
source contracts. Независимых subagents не было. Эти проверки не принимают
полный M1/MVP и не закрывают оставшиеся backend/system пробелы.
