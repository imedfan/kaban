# BE-30: пробные запуски моделей

27 октября 2026. Ветка `codex/be-30-model-probes` от проверенного после
`git fetch origin` main `b56dece`. BE-24/BE-25 отсутствуют в этой базе и среди
доступных remote refs. Этот инкремент подключает producer проб к существующему
runtime; он не объявляет завершёнными production prompt/stream, классификатор
реального CLI или Seatbelt из соседних задач.

## Поведение

`runRuntimePass` вызывает `runModelProbePass`: он запускает сохранённый Cursor
executable с окружением BE-23, явной моделью, коротким промптом и `stream-json`.
Проба работает в отдельном пустом каталоге, без task token, resume и `--force`.
У неё отдельная process group, birth identity, минутный deadline и ограничение
чтения stdout/stderr в 64 КиБ на поток. Неизвестный вывод, подмена/отсутствие init,
неуспешный result, инструменты, timeout или неизвестный exit не считаются успехом.
Чистый результат требует exit 0, init с подтверждённым каталогом именем и
успешного result. Классификатор проверяет также stderr; дата сброса сохраняется.

Две silent-задачи одной модели делят пробу. Результат адресуется сохранённым
`taskId + lastRunId`, поэтому отмена, перенос или новый run не принимают старый
результат. Чистая проба передаёт `probeFinished(.clean)` в автомат: он списывает
исходную попытку и автоматический run задним числом, назначает backoff либо
`retries_exhausted`/`run_limit`. В существующей истории корректируется
`countsTowardLimits`; отдельной записи run пробы нет. Лимитный результат не
списывает попытку. Один результат устанавливает флаг один раз независимо от числа
ждущих задач; auth-ошибка также не расходует попытку.

Проба не меняет stage/project admission. Она учитывается в `maxConcurrentRuns`
вместе с reservations задач и ещё останавливающимися физическими процессами.
При полном потолке ждёт без вытеснения; начавшись, блокирует следующий task start.
Проверка и reservation сериализованы тем же store lock, что команды и scheduler.

## Хранение и повтор

Additive migration `model_probe_process_v24` добавляет отдельное состояние
процесса и расписание проб квоты. На модель допускается один процесс и не чаще
600 секунд от фактического admission, включая неуспешный spawn. Ожидание свободного
слота не расходует интервал. Identity пишется до разрешения exec через start gate;
неподтверждённый launcher после crash не запускает CLI.

Наблюдённый typed результат сначала сохраняется, затем применяется транзакцией
вместе с флагами, task transitions, journal и finished marker. Откат этой
транзакции допускает повтор после reopen без второго списания. PID reuse не
сигналится; потерянный после restart exit code не объявляется чистым результатом.
Такая неопределённая проба повторяется после интервала. Это не exactly-once
внешнего процесса. Краткоживущие raw outputs удаляются после результата; повтор
runtime также удаляет остаток после crash между commit и cleanup.

`usage_exhausted` без даты сохраняет `resetsAt=nil`. Шесть часов — срок до
следующей пробы, а не дата автоматического снятия. Чистая проба снимает только
наблюдённый scope, причём generation защищает более новую ошибку того же пула.
Известная будущая дата блокирует пробы до сброса. Model flag снимается только
подтверждённой чистой пробой; существующее снятие `unavailable` при возврате в
каталог сохранено. Известная дата из текста продолжает истекать по времени.

Добавлена additive wire-команда `clearUsageFlag(pool?)`: `nil` снимает только
unknown-флаг Мака, `.cm`/`.om` — выбранный пул. Receipt и correlated
`settingsChanged` атомарны, capability объявлена. Старые payload/fixtures не
меняются, версия протокола — 1. Добавление кнопки в App не входит в backend-правку.

## Проверки

Успешны unsigned `xcodebuild` App/helper, `python3 tools/check-project-context.py`
и `git diff --check`. `tools/smoke-daemon-transport.py` прошёл на настоящих
процессах и временной БД. Native `--ui-smoke` прошёл на настоящем WindowGroup:
create/edit/move/cancel, pause/resume, projection/search и Cmd-N/Cmd-F. Первый
native запуск дошёл до connected/projection, но не получил keyboard focus;
повтор с `open -n -W -F` прошёл. UI-композиция этим инкрементом не менялась.

Первый полный Swift прогон внутри sandbox остановлен: системные Git-вызовы
добавляли `confstr` warning в вывод, `sandbox-exec` не мог применить профиль,
localhost MCP был запрещён. Assertions не ослаблялись. Итог полного повтора
вне sandbox и финального regression-прогона фиксируется после их завершения.
Новые process tests используют исполняемый синтетический CLI, а не платный Cursor:
совместный результат, backoff и exhausted, WIP=1, потолок 4 и ожидание места,
10 минут/6 часов, сохранение unknown usage через 7 часов, scope ручного снятия,
model confirmation/catalog, override, restart, cancellation, timeout, новая
ошибка во время пробы, SQL rollback/reopen и настоящий `runRuntimePass` без
тестового task runner. `M1-SILENT-01` расширен шагом результата пробы, Kit replay
выполняет его, BoardCore replay проверяет сгенерированные события.

## Границы

Живые платные prompts, installed helper и системная регистрация в этом поручении
не выполнялись. Реальная форма stream/init и debug-лога требует BE-22/BE-25;
production task prompt/stream — BE-24, профиль изоляции — BE-28. Проба использует
нынешний строгий parser и fail-closed сравнение с сохранённым каталогом: неизвестная
форма остаётся unconfirmed и не снимает флаг/не списывает попытку. Промпт «не
использовать инструменты» сам по себе не доказывает изоляцию реального CLI.

Старые usage-флаги с уже записанной искусственной датой неотличимы по старой схеме
от настоящей распарсенной даты и не переписываются миграцией. Исправлено создание
новых unknown-флагов; старое ошибочное состояние можно снять новой scoped-командой.
Полная live-приёмка BE-30 остаётся связанной с BE-22/24/25/28; fake/process tests
не закрывают полный M1/MVP.
