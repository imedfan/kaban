# BE-16: долговечные логи запусков

Дата: 6 октября 2026. Ветка `codex/be-16-run-logs`, база — `codex/be-13-incidents`
(`9f34c4d`, [PR #86](https://github.com/imedfan/kaban/pull/86), открыт поверх `codex/be-12-git-grants` и ещё не принят в main).
Очередь — [backend MVP](backend-mvp-tasks.md). Pull request открывается поверх `codex/be-13-incidents` и этим коммитом ещё не записан.

## Реализовано

`readLog` читает нормализованные `AgentEvent`. Смещение — номер записи, не байт JSONL. `nextOffset - fromOffset == events.count`. Пустая страница допустима только когда читатель догнал конец (`fromOffset == endOffset`). Нет строки лога или удалён файл `Logs/<run-id>.jsonl` — `log_unavailable`, не пустой успешный ответ. Обрезанный префикс — `log_offset_expired`, в `params.availableFromOffset` первое живое смещение. Хвост не перенумеровывается. Повтор того же смещения возвращает те же события.

Парсер — тот же `CursorStreamParser`. Недописанная строка хранится в `run_log.pending` и продолжается следующим куском. Наблюдатель процесса и прямой `ingestAgentOutput` вызывают одну функцию. `--log-pass` печатает страницу через этот же `readLog` и не запускает Cursor. `capabilities.readLog` — `true`.

Секреты вырезаются до записи лога, stderr, артефакта, вопроса, ответа и резюме. Шаблоны: `KABAN_RUN_TOKEN=…`, `Bearer …`, `sk-`, `ghp_`, `gho_`, `github_pat_`, `xoxb-`/`xoxp-`, `AKIA`, `glpat-`, `AIza` и PEM. Известный литерал длиннее 11 символов можно передать отдельно. Вместо значения пишется `<redacted>`. После выхода процесса сырые stdout/stderr тоже переписываются. `CursorLimitClassifier.redact` для артефактов не используется: он заменяет весь текст одной фразой.

В одном запуске хранится не больше 1024 событий и около 1 МиБ файла. Более старые строки удаляются, номера оставшихся не меняются. Снимок и `getTaskDetail` больше лимита сообщения (8 МиБ) возвращают `snapshot_too_large` и `detail_too_large` с `bytes` и `limit`. Сохранённый заголовок и артефакт при этом не укорачиваются. `getRunHistory` отдаёт только запуски и остаётся путём восстановления. Резюме стадии больше не режется вторым молчаливым пределом в 8192 байта. Вывод одного hook/gate по-прежнему ограничен `StageCommand.outputLimit` и помечается `[truncated]`.

`readLog` ничего не удаляет и не ждёт клиента. Следующий tick планировщика после частичного чтения стартует другую задачу. Прогресс по-прежнему можно схлопнуть в эфире. Переходы, запуски, артефакты, вопросы и ответы лежат в `task_detail` и переживают обрезку журнала `event`. `TaskDetail` из журнала не собирается.

## Границы

Файл JSONL переписывается внутри callback записи SQLite, но сам файл транзакция не откатывает. Обрыв между записью файла и commit может оставить файл впереди строк; следующий ingest переписывает его из строк. `readLog` при пропавшем файле отвечает `log_unavailable`, даже если строки ещё есть. Это не exactly-once внешнего процесса. Merge остаётся BE-17. `restoreWIP`, среда Cursor и allowlist MCP по-прежнему не поддержаны. Обычный запуск демона не читает лог, пока не передан `--log-pass`.

## Проверки

- Повторное чтение того же смещения совпадает. Следующее смещение продолжает без пропуска и дубля. Разрезанная NDJSON-строка склеивается. Догнавший курсор получает пустую страницу. Удалённый файл — `log_unavailable`.
- 1027 событий оставляют смещения с 3. Чтение с 0 — `log_offset_expired` и `availableFromOffset=3`. С 3 идут `n3`, `n4`, затем `n5`, `n6`.
- Резюме `complete_stage` и поток процесса не содержат значение run-token и `sk-…`. В артефакте, JSONL, stderr и сырых файлах процесса после выхода стоит `<redacted>`.
- Резюме из 20000 символов возвращается целиком. Заголовок длиннее 8 МиБ не урезается в строке задачи. Снимок и detail отвечают `snapshot_too_large` / `detail_too_large`. `getRunHistory` остаётся успешным. После `discardJournal` длинный заголовок и резюме на месте.
- Частичное чтение не съедает лог. Пока читатель на первом событии, tick ставит следующую задачу в dev и следующим tick запускает её. Хвост лога читается с прежнего `nextOffset`.
- Вопрос, ответ, запуск и лог переживают `discardJournal` и повторное открытие базы.
- Два `--log-pass` печатают один stderr: `log page-log 0 1 1 complete`.
- macOS: `KABAN_SCENARIOS=Scenarios/M1 swift test --filter RunLogTests` — 7 tests, 0 failures. Полный `KABAN_SCENARIOS=Scenarios/M1 swift test` — 484 tests, 0 failures (Transport 23, Protocol 64, Kit 180, DaemonCore 151, Board 66).
