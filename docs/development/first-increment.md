# Первый инкремент разработки MVP

2026-10-04. Координатор: текущий чат. Architect/Analyst, Backend и Frontend —
субагенты gpt-6.1-sol medium. Дизайнерские работы исключены.

## Backend M1

Сначала исправить подтверждённые дефекты Kit; затем создать GRDB store и
KabanDaemonCore с одной транзакцией на команду: текущее состояние, transition,
journal и effect outbox атомарны. Проверить rollback при ошибке, повтор commandId,
reopen БД и восстановление running при рестарте. Side effects выполняются после
commit и подтверждаются отдельно. В outbox сохраняются точные payloads, а не
результат повторного вычисления по новой версии автомата.

Первый инкремент использует внутренний durable snapshot; fake driver ещё не реализован;
полный wire getSnapshot/TaskDetail, durable incidents/grants, scheduler fairness,
WIP, квота, реальные git/Cursor/MCP, XPC и kabanctl — следующие шаги. Частично
реализованная поверхность не должна выглядеть как готовый production daemon.

## Frontend — шесть этапов

1. SwiftUI app target macOS 26, shell, semantic card presentation, mock-клиент,
   несколько дорожек и выбранная задача. Проверяем unsigned Xcode build.
2. Полный основной канбан: проекты/задачи/переносы/пустые состояния.
3. Лог, попытки, вопросы, Human Review, git permissions, подозрительные файлы.
4. Pipeline/стадии/модели/git/MCP/квота и настройки.
5. Сквозная интеграция XPC, reconnect/resync, менюбар/уведомления/службы.
6. Сценарная приёмка, доступность/нагрузка/восстановление, подпись/нотаризация.

App зависит только от Protocol и BoardCore, не Kit/GRDB. Семантические переходы
задач подтверждает клиент демона: UI отправляет команды и принимает события,
не меняет статус оптимистично. Mock демонстрирует эту границу, не заменяет живой
исполнитель. Готовые tokens/макеты — источник реализации; редизайна нет.

## Критерии приёмки инкремента

- Все новые PR имеют актуальный зелёный Linux/macOS CI; app отдельно собирается
  на доступном Xcode, целевое macOS 26 отдельно от фактического хоста.
- Старые и новые тесты проверены вместе в временном checkout.
- Решения issues, изменения public wire и ограничения записаны в документах.
- В Git нет credentials, токенов, персональных fixtures или DerivedData.
- Полный M1/MVP не объявляется готовым по одной persistence-вертикали или mock UI.
