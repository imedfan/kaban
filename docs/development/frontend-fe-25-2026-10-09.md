# FE-25: русские тексты диагностик пайплайна

9 октября 2026. База после fetch — main `ec20437`, спека v0.8.26 и
архитектура v0.11.27. Ветка `codex/fe-25-validation-texts` независима от draft
FE-21. Реализация и native captures — source `3411f35`.

## Изменённое поведение

ValidationIssueText покрывает все 40 текстов §4.1. Исправлены ключ invalid_id,
полный текст ограничения идентификатора, root type_mismatch, пунктуация Done
и returns_not_allowed, пояснение первого слова git-правила. Добавлены тексты
pipeline_missing, pipeline_invalid и git_policy_rule_not_allowed.
37 текущих Protocol constants проверяются явно. Три остальных кода пока
передаются демоном строками в StorePipelines и StoreGit; перенос этих значений
в ValidationCode относится к BE-34 и не меняет способность UI их переводить.

Редактор, проектные ошибки, плашка на доске и git policy preview используют
общий перевод. Пустой диагностический path показывается как pipeline.yaml.
Неизвестный код сохраняет message и выводится моноширинным в metadata;
известный код без нужных params сохраняет весь исходный message, без частичной
подстановки. Возвраты/duplicate_id, подписи лимитов и длительности сохраняют
контекст и значения сервера. Клиент не вычисляет границы и не валидирует YAML.
Severity приходит от сервера и определяет доступность применения.

Композиция редактора сохранена по [pipeline v0.2](../../design/v0.2/png/04-pipeline-invalid.png).
На настоящем minimum окне жёлтый warning оказался бледным на белом фоне.
Теперь текст использует существующие foreground tokens waiting/incident
вместо системных yellow/orange. После этого обе темы пересняты.

## Проверки и критерии

| Критерий FE-25 | Доказательство | Результат |
|---|---|---|
| Словарь и тексты §4.1 | 6 ValidationIssueTextTests, snapshot 40 сообщений, все 37 существующих Protocol constants | пройден |
| invalid_id без params | regression test и реальный validation DTO в native App | пройден, полный текст v0.8.26 |
| Root type_mismatch | [] через production validatePipeline; пустой path и настоящий экран | пройден, path отображается как pipeline.yaml |
| Три дополнительных кода | snapshot по принятой DOC-06; существующие producers StorePipelines/StoreGit и общие UI consumers | UI переводы реализованы; BE-34 constants отдельно |
| Fallback для legacy/неизвестного кода | exact braces/message, отсутствующее имя стадии, max_file_mb без min/max, моноширинный code в views | пройден |

До исправления три теста показали конкретные несовпадения:
invalid_id вернул `Invalid stage identifier`, root type_mismatch —
`Неверный формат поля `, git warning — текст без `(только первое слово правила)`.
После исправления эти три теста прошли. Затем полный BoardCore прогнал
217 tests, 0 failures, включая 6 новых tests и nearby PipelineEditor/IdentityDraft.
Изменение затрагивает только presentation и существующий opt-in QA.
Protocol, validator, daemon commands, pending outcomes и файлы пайплайна не менялись.

Финальный App build прошёл. Два native minimum запуска проверили root, invalid-id
и warning в настоящем WindowGroup через bundled production daemon/private stdio.
Error блокирует Apply, warning допускает Apply; после всех previews исходный
working файл и committed текст не изменились. Cursor и установленный helper
не запускались. Seed — новый временный репозиторий с явным synthetic YAML.

[Checks](screenshots/fe-25/checks.json) и [manifest](screenshots/fe-25/frames.json)
содержат source, размеры и SHA-256 шести actual WindowGroup кадров 2080×1280.
[Светлый warning](screenshots/fe-25/git-warning-light-minimum.png),
[тёмная длинная ошибка](screenshots/fe-25/invalid-id-dark-minimum.png) и
[тёмный warning](screenshots/fe-25/git-warning-dark-minimum.png) просмотрены
после финальной смены цветов. Все шесть финальных кадров просмотрены;
root и длинный invalid-id текст видны полностью в обеих темах.

Среда: Apple Silicon, Swift 6.4, Xcode 27.0 (27A266a), macOS 27.0.1 (26A434).
Новый отдельный VoiceOver/keyboard проход для этих текстов не выполнялся.
CI нового PR проверяется отдельно от локального результата и старых PR.
Полный основной сценарий FE-22 остаётся открытым вместе с BE-21–41/PRE-01.
