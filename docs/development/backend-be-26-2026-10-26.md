## Поведение

- Host без диагностических pass-флагов до запуска scheduler создаёт один
  `MCPBoardServer` на случайном `127.0.0.1` порту. `/mcp` и `/git/check`
  используют этот сервер; host пишет только URL в stderr. Сервер живёт до shutdown.
- Env каждого run включает `KABAN_MCP_URL`, `KABAN_GIT_CHECK_URL` и новый
  `KABAN_RUN_TOKEN`. PATH/toolchains берутся из сохранённой Cursor environment;
  HOME/XDG_CONFIG_HOME отделены от личного профиля. Preflight и процесс агента
  получают одинаковые cwd/env. Raw token в конфиг и SQLite не записывается.
- Конфиг содержит kaban и пересечение выбранных серверов стадии с allowlist.
  Args/env/headers выбранных серверов сохраняются; разные определения одного
  имени не сливаются. Отсутствующий выбранный разрешённый сервер блокирует run.
- `mcp list` имеет timeout и ограниченный output. Лишнее имя, нечитаемый config,
  неуспешный exit или непонятный вывод блокируют запуск. Проект получает
  `mcp_unexpected` с именем/диагностикой. Резервация возвращается в queued,
  attempts и max-runs не расходуются, процесс не создаётся.
- `recheck(project)` выполняет свежий preflight в отдельном scratch каталоге,
  с изолированным HOME и конфигом актуальных committed agent-стадий. Без host
  или runnable CLI прежний результат сохраняется. Снять блок может только
  успешная проверка; runtime снова проверяет конкретный run перед spawn.
- Tracked `.cursor/mcp.json` временно имеет skip-worktree; новый файл исключён
  через info/exclude. До gates/result check, при stop/WIP rollback и recovery
  swap снимается; result check возвращает файл к версии main. Обычный агентский
  `git add -A` не добавляет run-конфиг в коммит. Это не граница защиты от агента,
  намеренно меняющего git index: Seatbelt остаётся BE-28.
- v23 хранит ответ complete/return/question в одной транзакции с переходом,
  journal и outbox. Повтор финального вызова тем же токеном возвращает receipt,
  не расходует bounce limit и не создаёт второй вопрос. Metadata/progress/git
  с отозванным токеном отклоняются; recovery помечает все прежние токены
  `restart_revoked`, включая токены с финальными receipts.
- Поддержаны MCP initialized notification и схемы аргументов пяти tools.
  Соединения ограничены, имеют read/write timeout и защиту от SIGPIPE;
  сокеты не наследуются через exec агента.

## Границы

Live-критерий BE-26 и BE-10 «Auth/сборка/MCP работают в реальном профиле»
не закрыты. Настоящая модель Cursor не запускалась. До BE-22 парсер принимает
проверяемую форму `name<TAB>source`; другой формат блокирует run, а не считается
пустым списком. Реальные формат `mcp list`, подхват `${env:KABAN_RUN_TOKEN}`,
авторизация отдельного HOME и вызов complete_stage требуют BE-22/BE-24.
Штатный Cursor prompt/stream, shim (BE-27), production Seatbelt (BE-28),
installed LaunchAgent и полная native FE-16 приёмка не проверялись этим срезом.
Обычный host без `--runner` оставляет agent starts pending.

Наличие HTTP endpoint и успешных тестов с фейковым агентом не означает
готовность полного M1/MVP.
