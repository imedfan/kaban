# FE-04: нативное управление локальными проектами

7 октября 2026. Ветка `codex/fe-04-project-lifecycle`, отдельные коммиты задачи.
Проверенная после fetch база main — `0dcfd91`: FE-03 принят через
[PR #94](https://github.com/imedfan/kaban/pull/94). Только коммиты FE-04 перенесены
на эту базу. Сравнение дерева до/после rebase не выявило изменений исходников.

## Реализованный сценарий

Добавление доступно в сайдбаре и на пустой доске. Нативный лист содержит папку,
NSOpenPanel и включённый по умолчанию шаблон `.kaban/`. Первый запрос отправляется
без identity. git/config читает демон; views не дублируют его проверки.
`identity_required` раскрывает поля по params: найденные значения отмечаются,
первый missing не подсвечивается, invalid получает текст; повторный отказ
подсвечивает только указанные поля оранжевым. Фокус следует IdentityDraft.
Non-git, duplicate, недопустимая ветка и доступ отображаются как typed отказ
в том же листе. Папка, галочка и введённый автор сохраняются.

`ProjectLifecycleStore` использует общий BoardSession и durable journal. Черновик
с commandId сохраняется до отправки, pending восстанавливает прежний envelope
и блокирует второе действие. Ответ `.ok` не создаёт дорожку. Applied подтверждает
correlated event либо исходный receipt и покрывающий authoritative snapshot
по контракту FE-02. Journal сохраняет projectId из projectAdded; после retention
точное совпадение нормализованного path позволяет выбрать проект из snapshot.
Неизвестный canonical alias не угадывается: остаётся переход к доске.

После подтверждения лист читает listBranches/detectGates/checkEnvironment через
тот же клиент. Проверяет capability, commandId и тип результата; старый read
прежней формы/сессии отбрасывается. Пустой список гейтов и неизвестная среда
различаются. Ветку не переключаем автоматически. Серверные no_pipeline и
pipeline_invalid позволяют Backlog, но показывают необходимость конфигурации.
Список дорожек App читает непосредственно из BoardSession; второй копии нет.

Relink/remove доступны в меню проекта и его настройках. Relink сохраняет ID,
задачи и историю. Remove требует отдельного подтверждения: объясняет отмену
незавершённых задач, остановку run, сохранение истории и очередь архивации веток.
Он убирает проект после authoritative изменения и возвращает настройки удалённого
проекта к доске; папка пользователя остаётся. Скрытие дорожки — отдельное действие.
Повторная проверка project использует capability/scopes и обычный journal.

## Доступ к папкам

App сохраняет security-scoped bookmarks выбранных NSOpenPanel папок отдельно
по источнику состояния, восстанавливает их при создании store, балансирует
start/stopAccessing и показывает stale/error с повторным выбором. Добавлен
`com.apple.security.files.bookmarks.app-scope`; основание —
[официальная документация Apple](https://developer.apple.com/documentation/professional-video-applications/enabling-security-scoped-bookmark-and-url-access).
Bookmark даёт доступ App и не доказывает права helper. Полная sandboxed
App/helper/restart приёмка остаётся открытой из-за BE-20. Эти проверки не заменены
developer stdio или фактом наличия entitlement.

## Проверки

- BoardCore после интеграции lifecycle FE-03: **103 tests, 0 failures**.
  Семь новых ProjectLifecycleStore tests проверяют refusal params/ввод,
  exact pending envelope, event-before-lost-reply, correlated relink/remove
  и malformed/stale reads. Отдельный тест подтверждает проект без доставки
  projectAdded: сохранённый receipt покрыт authoritative snapshot, один commandId. Сохранённая форма не повторно накладывает старый отказ
  поверх исправленного ввода при открытии.
- Существующие `ProjectLifecycleTests`: **14 tests, 0 failures**. Это настоящий
  локальный git/SQLite через KabanStore, включая invalid/non-git, template,
  no_pipeline, relink, remove/running cancellation, replay и внешние git races.
  Это store tests, не замена native/XPC проверки.
- Unsigned App `xcodebuild`: **BUILD SUCCEEDED**.
- Native developer `--project-smoke` с bundled daemon и private БД: **passed**.
  Проверены реальные non-git, первый invalid git identity и повтор с invalid/missing,
  сохранение folder/template, отсутствие ложного проекта; затем Add → Backlog →
  reopen DB → Relink → Remove. Исправленный identity передаётся буквально.
  Отдельный прогон с существующим невалидным pipeline также прошёл.
- Native `--ui-smoke --qa-project-form first`: **passed**. Прежние create/edit/move,
  pause/resume/cancel, поиск/фильтры и Cmd-N/Cmd-F; дополнительно Return отправляет
  AddProject, native field editor получает missing email, Escape закрывает лист,
  повторное открытие сохраняет path/template/identity.
- Context checker и diff check: **PASS**. CI FE-04 проверяется
  отдельно по опубликованному HEAD; результат CI FE-03 его не заменяет. PR в main
  содержит только FE-04; зависимость #94 принята.

Live QA сначала выявил повторный запуск уже закрытого stdio helper при reopen;
terminal close исправлен в FE-03 и проверен 29 Transport tests. Ещё один
строгий guard требовал projectAdded даже когда исходный receipt был покрыт
snapshot. Driver теперь допускает оба доказательства, требует exact envelope,
положительный seq, покрывающий stateSeq, правильный path и ровно одну дорожку.
Сам acceptance не проходит guard; модель/требования не упрощались.

## Оставшаяся приёмка

Первые три критерия FE-04 проверены. Четвёртый — реальный App/helper folder grant
после restart — остаётся открытым. Не проверены штатный signed XPC, системная
регистрация, платный Cursor или уведомления. Branch picker с произвольной базовой
веткой не обеспечен текущим wire/backend: поддержана локальная main. Редактирование
гейтов требует FE-13 pipeline draft. Это не изменения продуктовых требований;
расхождения описаны в [backend integration gaps](frontend-backend-integration-gaps.md).
Недостающие дизайнерские состояния — [отдельный файл](frontend-design-gaps.md).
