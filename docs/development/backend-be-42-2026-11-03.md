# BE-42: корневая `.kaban/` без коммита

База: `origin/main 82168859a0da33a383d68be3ce612d57717be12c`, проверена через
`git fetch origin` 2 и 3 ноября 2026. Ветка: `codex/be-42-project-pipeline`.
Код и тесты: `b61773a`. Исходные локальные решения/определения BE-42 и FE-35 сохранены.

## Поведение

Регистрация, startup, `recheck(project)`, FSEvents и fallback polling читают
рабочую `.kaban/` корня проекта. Git-объекты, выбранная базовая ветка, индекс
и `.gitignore` не определяют содержимое пайплайна. Базовая ветка всё ещё нужна
для клона/rebase/слияния и должна существовать локально. Gate detector
по-прежнему использует build descriptors выбранной базы.

Шаблон создаётся файловым durable intent на любой текущей ветке. Он содержит
пустые модели и ожидаемо блокирует запуск с `pipeline_invalid`; Backlog доступен.
Существующие `.kaban/` файлы не перезаписываются. Шаблон и `updatePipeline`
не создают git commit, не меняют refs/index и не переключают ветку. Чтение
ограничено 16 МиБ, 1024 entries и глубиной 32; дескрипторы с `O_NOFOLLOW`
отвергают симлинки и специальные файлы. Отсутствие каталога/YAML публикует
`pipeline_missing`; исправление/возвращение источника восстанавливает состояние.

Запуск сохраняет immutable `PipelineVersion`/RunSpec. `get_task_context`
дополнен optional `pipelineVersion`, `stage`, `gitPolicy` из этого RunSpec.
Промпт требует получить MCP-контекст и передаёт абсолютный путь к скиллу
`<project>/.kaban/…`. Корневые файлы принадлежат пользователю и доступны агенту
только на чтение через существующий запрет Seatbelt на запись в репозиторий.
Зафиксированная версия запуска не превращает живой файл по этому пути в
неизменяемый файл: пользователь может редактировать его во время run.

В клон `.kaban/` специально не копируется и в exclude не добавляется.
Закоммиченная копия приходит обычным git-путём. Специальный запрет `/git/check`,
deny Seatbelt и result incident для `.kaban/` клона удалены. Агентские изменения
могут слиться; источник изменится только когда соответствующие байты попадут
в рабочую корневую `.kaban/`. Остальные правила git/read-only/suspicious files
продолжают действовать. `kaban_dir`/`kaban_dir_changed` сохранены как legacy ids.

## Совместимость и восстановление

Миграция v26 кеширует наблюдаемые источники, включая невалидные, по sourceHash.
Она позволяет подтвердить точный YAML, уже записанный редактором и принятый
наблюдателем до команды «Применить». Конкурентные изменения другого asset
отклоняют устаревший draft. Снимки и версии неизменны; повтор команды возвращает
прежний receipt, recovery сохраняет более позднюю правку пользователя.
Legacy поля commit/blob/index в durable plans по-прежнему декодируются,
но новые операции не публикуют git refs. Legacy JSON wire fixtures сохранены;
в их ожидаемых значениях зафиксирован исторический список из семи инвариантов.

Имена `PipelineSourceContent.committedContent`/`workingContent` сохранены:
оба поля содержат текущий корневой YAML, hash относится к корневым assets.
`hasUncommittedEdits = false`, `uncommittedIssues = nil`; отдельного
неприменённого git-пайплайна теперь нет. Поддержка skills вне `.kaban/`
заменена новым требованием единственного корневого источника.
