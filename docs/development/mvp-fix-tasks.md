### 0.3 Определение готовности MVP (ручная сквозная проверка)

**Общее предусловие (PRE-01).**
- Мак Артёма, на нём залогиненный `cursor-agent`. Логин Артём делает сам, агентам логин и токены не передаются.
- Платные запуски `cursor-agent -p` (ответ Артёма 9.10): **2 на спайк 1** (BE-22) и **4 на финальную приёмку** (Артём добавил запуски; итого **6**). Один «запуск» = один платный старт `cursor-agent -p`; бесплатные команды (проверка входа, `--list-models`, `mcp list`, проверка из-под launchd) не считаются (уточнение архитектора); модель — **"grok 4.6 medium"** (так её назвал Артём). Точный id модели для CLI берётся из каталога моделей / `cursor-agent --list-models` во время спайка; это не запускает модель и бюджет не тратит.
- Платные запуски выполняет **сам Артём на своём Маке** и сам выдаёт разрешения в «Системные настройки → Конфиденциальность и безопасность». Исполнитель заранее даёт ему точные команды и пошаговую инструкцию, что нажать и что прислать обратно (логи, вывод).
- Спайк 1 (BE-22) проведён на этом CLI, его фикстуры лежат в `research/`. Без этого BE-24/25/26 не принимаются.
- Спайк 6 (BE-29) к приёмке не проводится: платного бюджета на него нет. Остаточный риск из арх. §13 записывается в отчёт как принятый.
- Сборка локальная, без сертификата Apple: ad-hoc подпись, без App Sandbox (ответ Артёма 9.10). Developer ID и проверка Team ID не входят в MVP.

**Шаги на чистой учётной записи данных** (новая БД, `~/Library/Application Support/Kaban` отсутствует). Платные только шаги 8–11 (запуски 1–4); остальные шаги, включая Human Review и merge, бесплатные.
1. Собрать локальный bundle с ad-hoc подписью (`tools/package-local-app.sh` или Xcode Release, **без** `CODE_SIGNING_ALLOWED=NO`), без App Sandbox; перенести в `/Applications`, открыть.
2. Онбординг регистрирует helper (SMAppService). При `requiresApproval` Артём вручную одобряет Kaban в «Системные настройки → Основные → Объекты входа» и, если macOS спросит, в «Конфиденциальность и безопасность» (шаги записаны в DOC-03); после этого статус «подключено». Никаких ручных запусков демона и SQL.
3. Онбординг или настройки Мака: путь к `cursor-agent` найден автоматически или указан вручную. `checkEnvironment` показывает версию, `authOK = true`, git и sandbox. Каталог моделей непустой, в нём есть модель "grok 4.6 medium" (её id подтверждён в спайке 1).
4. Перезапустить App: путь к CLI сохранился, демон не зарегистрирован второй раз.
5. Добавить тестовый git-репозиторий и **выбрать базовую ветку** из списка локальных веток (с подсказкой «i» «От этой ветки создаются ветки задач, в неё же вливается результат»; BE-31, FE-27). Шага гейтов нет: демон сам определяет команды по файлам сборки и молча ставит их гейтами на `dev` и `merge`; лист сообщает результат (BE-33, FE-26). Шаблон `.kaban/` закоммичен одним коммитом, на дорожке плашка «Пайплайн не запустится: нет модели у …» с кнопкой «Указать модели».
6. «Указать модели»: **полный шаблон** (Dev, Test, AI Review — вариант (б), решение Артёма 9.10), у всех трёх агентских стадий модель "grok 4.6 medium". Флаг пропал, демон закоммитил `.kaban/`.
7. Создать **одну** задачу с заголовком, описанием, критериями приёмки и приоритетом; формулировка такая, что агент на Dev должен задать вопрос (например, в описании не указан выбор, который нужно уточнить).
8. **Платный запуск 1 — `dev`, вопрос.** В течение тика планировщика задача в Dev, `running`.
   - Процесс `cursor-agent` реально запущен с `--model <id "grok 4.6 medium">` и промптом: видно в `ps` и в живом логе.
   - В клоне `.cursor/mcp.json` собран демоном и содержит только сервер доски.
   - `git` в PATH агента — shim.
   - Агент работает внутри Seatbelt-профиля.
   - Агент вызывает `request_human` → задача `waiting_human: question`; приходит **уведомление macOS** с «Ответить», в **менюбаре** растёт счётчик «ждёт человека» (FE-21). Артём отвечает из карточки или из уведомления (BE-26, FE-10).
9. **Платный запуск 2 — `dev`, продолжение после ответа.** Агент получает ответ, продолжает, коммитит, в живом логе `report_progress`, затем `complete_stage`. По `complete_stage` на выходе стадии запускаются гейты: задача проходит `gating`, гейты зелёные, есть коммит в ветке `kaban/<id>-<slug>`.
10. **Платный запуск 3 — `test`.** Стадия Test на "grok 4.6 medium" завершается `complete_stage`, задача идёт дальше.
11. **Платный запуск 4 — `ai-review`.** Стадия AI Review на "grok 4.6 medium" завершается `complete_stage`; задача попадает в Human Review (`waiting_human: review`). Приходит уведомление о ревью (включено по умолчанию), задача видна в менюбаре; клик по уведомлению открывает её (FE-21).
12. **Без платных запусков.** В Human Review видны резюме стадий, файлы с +/−, коммиты и вывод гейтов. «Открыть в Cursor» открывает клон. «Одобрить». Merge: rebase, гейты, fast-forward **выбранной базовой ветки** в репозитории. Задача `done`, клон удалён с задержкой. `git log <база>` показывает коммиты задачи с автором из `GitIdentity`.
13. Перезапустить Мак: helper поднялся один раз, доска, менюбар и история на месте.

**Краевые проверки** (обязательны для MVP). `request_human` проверен вживую (шаги 8–9); на остальные платного бюджета нет, они проходят на **фейковом агенте** (скрипт по фикстурам спайка 1) через штатный демон:
- базовая ветка без `main` (например, `master`) и несуществующая ветка → «Локальной ветки «{branch}» нет в этом репозитории» (BE-31, FE-27);
- запрещённая git-команда → мгновенный отказ, запись в ленте, «Разрешить один раз», повтор проходит (BE-26/27, FE-17);
- `cursor-agent` разлогинен → баннер «Cursor недоступен…» и одно уведомление, задачи `queued`, «Проверить снова» после логина снимает флаг (BE-23, FE-20, FE-21). Проверка бесплатная, на живом CLI: модель не запускается;
- модель стадии с неверным именем в `system/init` → `waiting_human: model_substituted` (BE-25) — **только на синтетической фикстуре**; живую подмену модели вызвать нельзя, это записывается как известное ограничение (UC-22);
- молчаливый выход → проба → флаг или списание попытки, задача не висит (BE-30);
- агент правит `.kaban/` или `main` → `waiting_human: incident`, уведомление с повышенной важностью (BE-13, FE-21).

Отчёт приёмки различает mock, developer stdio, фейкового агента и штатный XPC на локальной ad-hoc сборке; для каждого платного запуска — модель, id, время и результат. В нём записаны SHA, версия CLI и macOS (требование FE-22).

## PRE. Предусловие (выполняет Артём)

### PRE-01. Залогиненный Cursor CLI, бюджет платных запусков, разрешения macOS
- **Приоритет:** P0 (предусловие, а не задача разработки).

- **Решение Артёма (9 октября):**
  - платные `-p`: **2 запуска на спайк 1** (BE-22) и **2 запуска на финальную приёмку** (Артём добавил запуски; DoD §0.3: одна задача на полном шаблоне — запуск 1 `dev` с `request_human`, запуск 2 `dev` после ответа, запуск 3 `test`, запуск 4 `ai-review`); **итого 6**; на спайк 6 (BE-29) бюджет не выделен;

  - модель всех платных запусков — **"grok 4.6 medium"** (как назвал Артём). Точный id для `--model` берётся из `cursor-agent --list-models` или каталога моделей Kaban; это не запускает модель и бюджет не тратит;
  - запуски делает **сам Артём на своём Маке** и сам выдаёт разрешения в «Конфиденциальность и безопасность» и «Объекты входа».
- **Что делает исполнитель:** для каждого запуска заранее готовит для Артёма точный список команд и шагов (что запустить, какие окна одобрить, какие файлы прислать), чтобы каждый платный запуск дал результат с первого раза.
- **Вне объёма:** передача логина, токена или `CURSOR_API_KEY` агентам; платные запуски сверх 2 + 4 без нового решения Артёма.
- **Критерии:**
  - [ ] Решение Артёма записано в `docs/decisions-log.md`: дата, 2 + 4 = 6 запусков, модель "grok 4.6 medium", Артём выполняет запуски сам.

## 5. Не для MVP (с причиной)

- **UC-21 / F25 проверка квоты** (producer, экран «Этот Мак» с квотой, согласие, `setQuotaOptions`) и **часть FE-20 про квоту** — **решение Артёма 2026-10-09**: вне MVP (также арх. v0.11.27). F25 — Should, опция выключена по умолчанию (спека §0, §4); реактивная схема UC-09 работает без неё. Экран «Этот Мак» остаётся с текстом «Данные квоты появятся после подключения источника состояния» (`BoardView.swift:547`).
- **Exactly-once внешних эффектов** (арх. обзор, «ограничения»): осознанное ограничение архитектуры, recovery описан (BE-18).
- **`settings = nil` без `--initialize`**: в штатном `--launch-agent` инициализация есть (`DaemonMain.swift:49`). Затрагивает только диагностику.
- **Подпись «Применить» в редакторе пайплайна** вместо «Сохранить» (UC-13 п.2): смысл совпадает, «Применить» по спеке §1.5 используется для ручных правок файла. Решение о подписи за дизайнером, на поведение не влияет.
