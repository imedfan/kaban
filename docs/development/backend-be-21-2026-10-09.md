# BE-21: локальная установка helper без App Sandbox

Дата: 9 октября 2026. База: `origin/main d94487e`, проверена fetch перед веткой.
Ветка: `codex/be-21-unsandboxed-helper`. Это отдельный инкремент BE-21,
не приёмка полного MVP.

## Изменения

- App Debug/Release отключают App Sandbox; sandbox entitlements удалены.
  Hardened Runtime, signing IDs и проверка code-directory hashes сохранены.
- Debug отключает отдельную debug dylib. На реальном ad-hoc запуске dyld
  отклонял `Kaban.debug.dylib` из-за отсутствия Apple Team ID. Library validation
  не отключается; Debug собирается одним исполняемым файлом.
- XPC listener получает исполняемый файл из `Bundle.main.executableURL`.
  LaunchAgent задаёт короткое `argv[0] = KabanDaemon`; прежний поиск bundle
  по argv завершал зарегистрированный helper ошибкой `notBundled`.
- Упаковка читает подписи готовых App/helper, требует их signing IDs,
  Hardened Runtime и отсутствие sandbox entitlement.
- Решение от 6 октября закрыто решением Артёма от 9 октября и архитектурой
  v0.11.27 §13. Другой Team ID, Developer ID и нотаризация не входят в MVP.

## Проверки

| Критерий | Проверка | Результат |
|---|---|---|
| Без Sandbox, с Hardened Runtime | Подписанный Release, `check-local-app-signing.py` | Пройдено на настоящих App/helper |
| Проверка обнаруживает регрессию | Копия Release переподписана с исходными sandbox entitlements | Ожидаемый отказ: `App Sandbox entitlement must be absent` |
| Debug и настоящее окно | Ad-hoc Debug; существующий `--ui-smoke` | Шесть проверок WindowGroup/typed actions/menu прошли |
| Ядро и сценарии M1 | `KABAN_SCENARIOS=Scenarios/M1 swift test` | 685 tests, 0 failures, 0 skips |
| Signing policy и XPC codec | `DaemonInstallationTests`, `XPCTransportTests` | 6 tests, 0 failures |
| Release без QA/demo | `check-app-build-contents.py` | Пройдено |
| Register/unregister | Отдельный `/Applications/Kaban-BE21.app`, существующий `--service-smoke` | `notFound → enabled → notRegistered` |
| Installed XPC | Тот же smoke после исправления пути helper | macOS вернула `requiresApproval`; нужен Артём |
| Restart/reboot/queue recovery | Требуется Артём и системная перезагрузка | Не проверено |
| requiresApproval/denied, TCC | Требуются реальные системные разрешения Артёма | Не проверено |

Исходное воспроизведение XPC сохранило `registered=enabled`, затем ошибку транспорта,
а в `~/Library/Logs/Kaban/daemon.log` было `KabanDaemon: notBundled`.
Это содержательный отказ до исправления; private anonymous XPC tests его не выявляли.

## Ручная приёмка Артёма и DOC-03

1. Собрать Release: `KABAN_LOCAL_DERIVED_DATA=/tmp/kaban-be21-release tools/package-local-app.sh`.
2. Скопировать готовый `Build/Products/Release/Kaban.app` в постоянный
   `/Applications/Kaban.app`, не поверх работающей старой сборки. Открыть App.
3. Если онбординг показывает требование одобрения, открыть его кнопкой настройки:
   «Системные настройки → Основные → Объекты входа и расширения», включить Kaban.
   Вернуться в App и повторить подключение. `enabled` без успешного XPC
   не считается подключением.
4. Только если macOS блокирует открытие приложения, открыть
   «Конфиденциальность и безопасность → Всё равно открыть». При запросе доступа
   к Documents/Desktop дать helper нужный доступ системным диалогом.
5. В меню «Служба» проверить перезапуск, отключение и повторное подключение.
   `launchctl print gui/$(id -u)/app.kaban.agent` должен показывать один pid.
6. Перезагрузить Мак, открыть App, проверить тот же единственный pid,
   сохранённую доску/историю и восстановление очереди.
7. Сохранить снимки настоящего онбординга/системных настроек для DOC-03.

После замены helper и повторной регистрации macOS вернула
`SMAppServiceErrorDomain Code=1`, статус `requiresApproval`. Smoke очистил
свою регистрацию. Успешный installed XPC после исправления пока не подтверждён.
Снимки ручных системных шагов отсутствуют. Эти критерии BE-21 и BE-20
остаются открытыми; фикстура `requiresApproval` не заменяет системное разрешение.
Тестовый bundle регистрируется только если службы до smoke нет и всегда
выполняет unregister. Существующая установка smoke не меняется.
