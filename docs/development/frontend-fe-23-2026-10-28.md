## Поведение

Один нативный блок `CursorEnvironmentView` доступен в онбординге и «Этот Мак».
Он показывает подтверждённый путь отдельно от редактируемого, версию, authOK,
git и sandboxOK, позволяет выбрать executable через NSOpenPanel или очистить
поле для discovery. Вход выполняет пользователь в Терминале; команда корректно
цитирует пробелы и апострофы пути. Login-инструкция не предлагается для отсутствующего
или незапускаемого executable. Применение пути не означает готовность runner:
причина флага остаётся видимой, даже если путь сохранён.

BoardSession сохраняет последнее применённое cursorEnvironmentChanged.
Даже correlated settingsChanged runner/catalog не подтверждает configureCursor:
CommandIntent требует именно cursorEnvironmentChanged.
RunnerEnvironmentStore не применяет ответ configureCursor сам: pending остаётся
до correlated event или существующего receipt + covered snapshot recovery.
Query, обогнавший event, не меняет применённую базу pending-команды; старый
report не перекрывает новое событие. Snapshot, пропустивший новое событие,
позволяет повторно прочитать свежую базу вместо вечного старого cache.
Discovery снимает отправленный nil-черновик после подтверждения разрешённого
пути; более новый ввод сохраняется. Отказ остаётся inline и не блокирует
исправленную отправку. При reopen uncertain-команда сохраняет исходный envelope.

## Конфигурация и открытая приёмка

Debug и Release собраны с `CODE_SIGNING_ALLOWED=NO`: сборки unsigned, без
App Sandbox, с проектной настройкой Hardened Runtime, но неподписанный bundle
не подтверждает его фактическое применение. Транспорт native-проверки — private
stdio. CLI отвечает только на --version, status и --list-models; модель, login,
платные запросы, регистрация LaunchAgent и системные permission requests не запускались.
Mach-O проверки различают Debug с QA и production Release без QA types.

Четыре критерия FE-03 на штатной ad-hoc установленной сборке остаются открыты:
чистая установка до первой задачи; requiresApproval/denied и возврат из Settings;
выбранный путь после перезапуска installed helper с настоящим Cursor login;
повторное открытие окна без второй регистрации и отдельный developer mode.
Private-daemon persistence подтверждена и не заменяет эти проверки.
Не проверены интерактивный выбор NSOpenPanel, физические Tab/Return, VoiceOver,
системная notification delivery/login items/TCC и установленный XPC.
Баннер над доской и FE-24-переход из пустого picker остаются вне FE-23.
