## Реализованное поведение

MenuBarExtra(.window) читает ту же BoardProjection: waiting count всех проектов,
список задач, резервирования, потолок запусков, optional квоту и flags.
Pause/resume/recheck используют существующие typed commands. Открытие задачи
показывает скрытый проект. Нет данных означает неизвестность, а не нулевую квоту.
Источник композиции — [quota v0.2](../../design/v0.2/png/06-mac-quota-menubar.png).
Соответствие самого popup макету ещё не подтверждено.

DaemonRuntime владеет подключением и native notification adapter. Закрытие
WindowGroup не отменяет subscription. Повторный переход поднимает существующее
основное окно. Quit синхронно останавливает клиентские subscriptions и сохраняет
неопределённые отправки. Код не вызывает unregister независимого LaunchAgent.
SMAppService.mainApp и permission controls переиспользуют OnboardingSystemState.
В developer/QA режиме регистрация автозапуска отключена.

AttentionStore принимает только применённые journal events и ephemeral events
после seq barrier. Snapshot создаёт baseline. Сохранённый seq, состояние задач
и глобальные flags подавляют replay, повторный snapshot, изменения заголовка
и отдельные task events при runner flag. Старые события и события при выключенной
настройке не доставляются позже. Incident имеет отдельный адрес и timeSensitive.

NativeNotifications хранит source, task/project/request либо incident и точный
текст ответа. Он проверяет актуальный detail и использует HumanAnswerStore,
command journal и correlated event. Старый вопрос, удалённая задача, другой
source, pending command и отличный сохранённый draft не отправляют новый ответ.
Отказ сохраняет текст. После restart автоматического повтора уже попытанного
ответа нет. Detached adapter отменяет свои delivery/routing tasks; поздний ответ
проверяет attachment и inbox ID.

## Критерии и ограничения

| Критерий FE-21 | Доказательство | Результат |
|---|---|---|
| Closed-window live updates и reopen | private stdio, typed settings event, одна доска после нескольких переходов | функциональная часть пройдена; popup не просмотрен |
| Permission denied и выключенная настройка | Core проверяет disable/reopen/no catch-up; adapter проверяет authorization перед add | системная delivery/denied приёмка открыта |
| Replay/reconnect/reboot и один runner notice | 5 AttentionTests: baseline, seq, replacement, reopen, global flag и новые tasks | Core пройден; системный reboot не выполнен |
| Актуальная задача и exact question reply | private daemon: stale reply сохранён без send, exact reply подтверждён событием, deleted target объяснён | общий маршрут пройден; click/reply из Notification Center открыт |
| Автозапуск штатной сборки | управление mainApp добавлено; регистрация в QA не выполнялась | открыто вместе с BE-20 |

Критерии всей FE-21 остаются открытыми. Клиентский код и проверки не выданы
за полную системную приёмку. Нет production quota reader/poller FE-20;
MenuBarExtra показывает факты и неизвестность этого источника.

## Ошибки, найденные проверкой

Replacement между humanRequested и обновлением карточки терял свежий question
notice. `testReplacementBetweenQuestionAndCardPreservesFreshNotice` сначала
выдал `nil` вместо `AttentionTarget.task(... requestID: fresh)`.
После исправления тест и весь BoardCore прошли.

Повторное openWindow создавало несколько досок. Private native smoke воспроизвёл
ошибку; revealBoard теперь поднимает существующее основное окно. Проверка учитывает
canBecomeMain и отличает доску от alert sheet. Light/dark сценарии оставили одну доску.

Async cleanup из applicationShouldTerminate с terminateLater зависала. Стек
собственного процесса показал AppKit _shouldTerminate в modal loop.
[Apple описывает этот режим](https://developer.apple.com/documentation/appkit/nsapplication/terminatereply/terminatelater).
Синхронный stopForTermination из applicationWillTerminate прошёл настоящий Quit
и проверку writer lease. Installed daemon lifetime этим private тестом не доказан.

## Воспроизведение и следующий шаг

```sh
KABAN_SCENARIOS=Scenarios/M1 swift test --filter KabanBoardCoreTests
xcodebuild -project Kaban.xcodeproj -scheme Kaban \
  -destination 'generic/platform=macOS' -derivedDataPath /tmp/kaban-fe21-app \
  ONLY_ACTIVE_ARCH=YES CODE_SIGNING_ALLOWED=NO build
swiftc tools/seed-human-answers.swift \
  -I .build/out/Products/Debug -I .build/checkouts/GRDB.swift/Sources/GRDBSQLite \
  .build/out/Products/Debug/KabanProtocol.o .build/out/Products/Debug/KabanKit.o \
  .build/out/Products/Debug/KabanDaemonCore.o .build/out/Products/Debug/KabanTransport.o \
  .build/out/Products/Debug/GRDB.o -lsqlite3 -o /tmp/kaban-fe21-seed
python3 tools/check-menubar.py --functional-only
python3 tools/check-menubar.py --functional-only --theme dark --minimum
python3 tools/check-menubar.py
```

Последняя команда остаётся строгой: без открытого popup она завершается ошибкой.
В этой среде CGPreflightPostEventAccess=false. У SwiftUI NSStatusBarButton нет
публичных target/action/gesture recognizers; AppKit event и accessibility press
не открыли MenuBarExtra. Новый системный запрос разрешения не делался.
Необходимы actual popup в обеих темах с long/empty/unknown/error/flags,
pointer/keyboard/focus/VoiceOver, реальная доставка/отказ permission, persisted
inbox после process restart, mainApp login и независимый installed helper.
FE-22 продолжает эту матрицу. Полный M1/MVP не принят.
