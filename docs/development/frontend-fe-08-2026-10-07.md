## Реализованное поведение

Сохранена композиция `03-task-details`: inspector 500 pt поверх доски,
ограниченный длинный заголовок, четыре вкладки и постоянный footer.
Описание сохраняет точный Markdown, включая переводы строк. nil означает
неполученный текст, пустая строка — пустое описание. Вопросы/ответы, feed,
summary/gate_output/diffstat/commits/hook/issue и неизвестные kinds используют
фактический TaskDetail. Неизвестный материал показывает тип и полный источник.

BoardSession перечитывает выбранную задачу при question/answer/progress,
переходах, files/grants/incidents и неизвестных событиях. In-flight события
буферизуются; publish требует task/generation/epoch/commandId и seq, покрывающий
все invalidations. Новое чтение объединяет накопленные уведомления. Feed и
материалы дедуплицируются по стабильным IDs и упорядочиваются; retained journal
не служит единственным источником истории. Общий stdio RPC не отменяется.

Loading, unavailable, empty, stale и detail_too_large различаются.
Ошибка остаётся в inspector и сохраняет последнее полное описание.
При обновлении header использует текущую projection, но editor baseline
остаётся исходной полной карточкой; до свежего detail редактирование закрыто.
Snapshot replacement сохраняет cache той же задачи до нового чтения;
смена selection удаляет чужие детали/историю.

Текст свыше 64 KiB открывается целиком в readonly/selectable NSTextView
с нативным поиском и copy. TaskArtifact.path показывается как metadata.
Наличие path не запускает чтение файла. clonePath=nil безопасен; явная кнопка
Cursor открывает только доступный путь через NSWorkspace и показывает отказ
при отсутствии папки или приложения. Цена/usage не вычисляются из времени.
Время показывается по-русски в часовом поясе Mac; DB running обозначается
резервированием, без обещания внешнего запуска процесса.

Run links открывают отдельное bounded readLog по runId; одна страница содержит
до 100 AgentEvents с полным Codable payload. getRunHistory работает отдельно
при недоступном TaskDetail. Это fallback FE-08; live tail, поиск по истории,
offset recovery и restoreWIP остаются FE-09. Решения по вопросам/review/files/grants
относятся к FE-10/11/18/20 и здесь не считаются реализованными.

## Проверки

- `KABAN_SCENARIOS=Scenarios/M1 swift test`: 582 tests, 0 failures:
  Transport 29, Protocol 66, Kit 180, DaemonCore 176, BoardCore 131.
- Пять новых BoardSession tests проверяют поздние reads при быстром выборе,
  сохранение cache при ошибке, coalescing question/answer/files/grants/incidents,
  snapshot replacement/retention, отдельную history generation, неизвестные
  kinds, nil clonePath, большие Unicode строки и отсутствие RPC cancellation.
- Дополнительно RunLog/MCP/StageGate suites: 28 tests, 0 failures.
  RunLog проверяет durable summaries/questions, retention и отказ wire oversize.
- Unsigned xcodebuild финального Kaban.app успешен.
- [Native detail smoke](screenshots/fe-08/native.json) в настоящем WindowGroup:
  открытый inspector получает progress/gate output по событию; oversize не
  теряет body, history/log читаются отдельно; 75 KB readonly source совпадает
  целиком, Escape закрывает sheet.
- [Первая сессия демона](screenshots/fe-08/live-first.json) и
  [повторный запуск](screenshots/fe-08/live-reopen.json): bundled stdio,
  отдельная SQLite DB/git repo, exact Markdown, durable question/answer,
  summary и readLog после удаления journal. App не восстанавливает их из fixtures.
- `tools/seed-task-details.swift` создаёт только новый временный каталог;
  run records резервируются через store APIs, Cursor не запускается.
  Pending manual effects могут дать gate failure из-за отсутствия clone;
  снимок показывает фактический retry_wait, не успешный production pipeline.
- CI сохраняет прежние strict keyboard/control smoke и добавляет detail smoke
  в тот же app build step. Exact-head результаты проверяются перед ready.
- Context checker и `git diff --check` выполняются перед публикацией.

## Визуальная проверка настоящего окна

[Manifest](screenshots/fe-08/manifest.json) фиксирует полный SHA кода, параметры
и SHA-256 кадров. Проверены 15 fixture состояний реального WindowGroup и два
кадра private daemon: minimum 1040×640 pt, обычное окно 1440×900 pt,
светлая/тёмная тема, длинный заголовок, описание, лента, сводка, история,
empty/loading/unavailable/too_large, неизвестный и крупный материал,
полный source sheet и отдельный log sheet.

В minimum окне заголовок занимает до трёх строк, вкладки остаются доступными,
body прокручивается, footer не обрезается. Summary/gate стоят перед metadata
commits; unknown/large показывают спокойную диагностику и отдельный полный
текст. Source sheet проверен в light/dark, log sheet — в dark без потери контраста.
Даты и статусы запусков локализованы. Original design tokens не заменены.

Это AppKit backing-store capture настоящего NativeShell/WindowGroup.
Attached sheets соединены существующим ReferenceExport; это не системный
compositor и не отдельный ReferenceFrameView.

## Границы приёмки

Локальные strict keyboard и control smoke не получили системный фокус:
active=false/key=false при видимом окне. Guards сохранены без ослабления;
[keyboard log](screenshots/fe-08/keyboard.log) и
[focus result](screenshots/fe-08/focus.json) фиксируют этот отказ на финальном App `96d9069a`.
Strict проверки должны пройти на финальном CI SHA. Native Escape проверки деталей не заменяют полный
физический keyboard/Tab сценарий.

Ручные pointer действия, физические клавиши, VoiceOver, system contrast,
Reduce Transparency, настоящий запуск Cursor по clonePath и installed signed
helper/XPC/reboot не проверены. Private DB reads не доказывают production
Cursor/MCP/gates. Полный M1/MVP остаётся открытым.

При слишком большом TaskDetail backend не предоставляет отдельное чтение
body/artifacts: cache сохраняется, история/лог доступны отдельно, неполученный
текст не выдумывается. [Точный backend пробел](frontend-backend-integration-gaps.md#fe-08-полный-текст-при-превышении-wire-размера).
Пять критериев FE-08 отмечены в границах этих проверок; следующая задача — FE-09.
Недостающие состояния дизайнера записаны в [отдельном файле](frontend-design-gaps.md).
