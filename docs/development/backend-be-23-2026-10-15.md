# BE-23: окружение Cursor в демоне

15 октября 2026. База после fetch — main `f405a27`, в котором приняты
FE-21, FE-25 и BE-21 через PR #115, #116 и #118. Реализация —
`codex/be-23-daemon-environment`, source `f9fbae9`.

Независимая от BE-22 часть реализована. Полная BE-23 остаётся открытой:
положительный login, каталог авторизованного CLI и installed launchd
требуют отдельной приёмки. Платные запуски Cursor и системная регистрация
в этом инкременте не выполнялись.

## Реализованное поведение

`getCursorEnvironment`, `configureCursor` и `checkEnvironment` поддержаны
в DaemonService. DTO сохранены. Golden fixtures содержат запросы, ответы,
`cursorEnvironmentChanged` и отказы. Неизвестный протокол отклоняется до
проб, относительный путь возвращает `cursor_environment_invalid`.
Несуществующий абсолютный путь сохраняется и даёт `agent_missing`.

Additive migration v22 хранит путь, PATH и разрешённые пути тулчейнов
JAVA_HOME, DEVELOPER_DIR, SDKROOT и GOPATH. Произвольный env и credentials
в эту запись не попадают. Старый runner_check без нового optional authOK
читается, сохранённый executable переносится при инициализации.

Discovery запускает login shell текущего пользователя. Из результата
читаются только путь CLI, PATH и пути тулчейнов. `configureCursor(nil)`
выбирает обнаруженный абсолютный путь и сохраняет его. Если CLI не найден,
повторная проверка может обнаружить его после установки.

`--launch-agent` и developer App с `--initialize` инициализируют окружение
до создания scheduler. При перезапуске используются сохранённые пути.
Чистый stdio-запрос kabanctl без `--initialize` не настраивает окружение.
`--runner` и `--cursor-agent` остаются developer-параметрами. Подключение
сохранённого окружения к платному AgentDriver относится к BE-24.

Пробы выполняются вне транзакции БД. Существующий projectOperations
сериализует настройку с проверкой раннера и каталогом. Конфигурация,
runner state, флаги, распознанный каталог, journal и wire receipt
фиксируются одной транзакцией. Повтор commandId возвращает сохранённый
ответ до чтения часов и внешних проб. Queries остаются свежими.

Раннер проверяется при старте, раз в пять минут и по recheck(runner).
Каталог обновляется при настройке, при старте и раз в сутки. Неизвестный
или ошибочный каталог сохраняет прежние модели. Отсутствующий раннер
блокирует новые резервирования, текущие запуски этим флагом не останавливаются.

checkEnvironment получает версию, подтверждение входа, git version и
результат короткой проверки sandbox-exec. Эта проверка подтверждает
доступность Seatbelt, полную изоляцию проверяет BE-28. Notification status
читается только в app bundle без запроса разрешения. В headless-процессе
notificationsAuthorized=false означает отсутствие подтверждённого разрешения.

Неизвестный status с exit 0 не подтверждает вход. До BE-22 поддержаны
прежние текстовые сигналы входа и выхода. Неизвестный формат блокирует
раннер как agent_not_runnable. Структурированный или изменившийся живой
формат требует фикстуры BE-22.

## Критерии и доказательства

| Критерий | Проверка | Граница |
|---|---|---|
| Startup без CLI, queued без reservation | Общая host initialization, реальный stdio-процесс и production scheduler test с отрицательным и положительным контролем | Installed launchd не проверен |
| Discovery и сохранение после restart | Фейковый login shell, путь с пробелами, новый KabanStore без исходного shell, сохранённые PATH и JAVA_HOME. Дополнительно живой CLI на Маке через stdio | Положительный login под launchd не проверен |
| Причины missing, not runnable, not logged in | Публичные команды, настоящий daemon и синтетический CLI. Разлогиненный живой CLI дополнительно проверен через stdio | Авторизация под launchd открыта |
| Каталог доступен сразу | configureCursor, listModels и correlated settings event в той же сессии | Использован табличный формат текущего matcher |
| Capabilities и wire | DaemonClient roundtrip, реальные pipes, Protocol golden и legacy fixtures | DTO не расширены |
| Атомарность и replay | Ошибка INSERT в journal откатывает конфиг, флаги и receipt. Повтор команды не запускает пробу снова | Пробы только читают состояние CLI |
| Отсутствие credentials в конфиге | Login shell с секретным sentinel, чтение фактического BLOB | В памяти остаётся окружение host |

Регрессия `testSuccessfulUnknownStatusDoesNotConfirmAuthentication`
проверяет `Usage: status [options]`, `Cannot determine whether logged in`
и `Not yet logged in` с exit 0. До исправления пробы возвращали
authOK=true и reason=nil вместо false и agentNotRunnable. Теперь
распознаются подтверждающие строки целиком или их известный префикс,
а не любое вхождение logged in. Этот тест и соседние runner/discovery tests
прошли. Финальный полный прогон source `f9fbae9` — 707 tests, 0 failures,
без skips: Transport 29, Protocol 70, Kit 181, DaemonCore 204, BoardCore 223.

`testSuccessfulRunnerRecheckRefreshesCatalogAfterLogin` выявил ещё один
переход: после неудачного обновления каталога и успешного логина recheck
снимал runner flag, но listModels оставался пустым до суточного обновления.
Проверка получила `[]` вместо `[after-login]`. Теперь восстановление
раннера сразу сохраняет распознанный каталог и его correlated settings event
в той же транзакции.

## Проверка настоящего компонента и App

`tools/check-cursor-environment.py` запускает штатный KabanDaemon через
private stdio с новой БД. Проверяет startup flag, три capabilities,
настройку, событие, replay, report, каталог, перезапуск и причины флагов.
CLI-fixture допускает только --version, status и --list-models.
После остановки host конфигурация читается отдельным SQLite connection.

Бесплатные пробы живого Cursor CLI `2026.09.23-86fc751` подтвердили
--version и поддержку status --format json. Status вернул exit 0,
isAuthenticated=false и текст о невыполненном входе. --list-models
вернул exit 1, авторизованный каталог не подтверждён. На новой БД
настоящий daemon выполнил configureCursor(nil), отправил correlated event,
вернул правильные path/version/authOK=false, установил agent_not_logged_in
и сохранил обнаруженный путь после restart. Installed helper при этом
не регистрировался. [Безопасная сводка бесплатных проб](../../research/be-23-free-probes-2026-10-15.json)
не содержит emails, токенов и raw account output. Это частичная проверка
BE-22 без модельных запусков, а не завершённый спайк.

Прежний `tools/smoke-daemon-transport.py` прошёл без ослабления ожиданий.
Он проверяет kabanctl, replay, retention, single writer, реальные Git
projects, pipeline reload, scheduler и историю.

Debug App build source `f9fbae9` прошёл. Native model-settings smoke на новой БД
прошёл 11 сценариев через bundled
production daemon/private stdio. Проверены темы, минимальный размер,
refresh, правила пулов, picker, override, missing model, substitution,
unconfirmed model и ошибочный refresh. Просмотрены settings-light и
settings-dark-minimum настоящего WindowGroup из финального прогона
`/tmp/kaban-fe14-0kwwrm35`. В этом повторе CLI синтетический.
Отдельный keyboard и VoiceOver проход не проводился.

Первая native-проверка обнаружила устаревшую fixture: запись только в
runner_check обходила сохранённую конфигурацию. Теперь check-model-settings
настраивает CLI через настоящую команду configureCursor и игнорирует
сохранённые окна macOS. Повтор прошёл с прежними assertions.

## Воспроизведение

```sh
KABAN_SCENARIOS=Scenarios/M1 swift test
python3 tools/check-cursor-environment.py --bin-dir "$(swift build --show-bin-path)"
python3 tools/smoke-daemon-transport.py --bin-dir "$(swift build --show-bin-path)"
xcodebuild -project Kaban.xcodeproj -scheme Kaban -configuration Debug \
	-destination 'generic/platform=macOS' -derivedDataPath /tmp/kaban-be23-app \
	ONLY_ACTIVE_ARCH=YES CODE_SIGNING_ALLOWED=NO build
python3 tools/check-model-settings.py --app /tmp/kaban-be23-app/Build/Products/Debug/Kaban.app
python3 tools/check-project-context.py
```

Скрипты создают новые временные каталоги и печатают их пути. Не используют
рабочую БД, пользовательские репозитории, регистрацию LaunchAgent или модель.
Discovery фейкового shell проверяется unit test. Положительный живой login,
авторизованный каталог и платный спайк остаются в BE-22.
