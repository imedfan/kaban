## Что исполняется

- На macOS configured task Cursor запускается через `/usr/bin/sandbox-exec`
  с профилем в argv. Непригодный профиль/отказ sandbox не имеет fallback на
  обычный exec. Родительский launcher ждёт прежний durable gate; process record,
  grant delivery и kill/recovery принадлежат прежней process group.
- Model probes BE-30 тоже проходят профиль. У них отдельные work/HOME/TMPDIR,
  пустой `.cursor/mcp.json`, нет run token и URLs доски, resume, force или MCP
  approval. Они не получают доступа на какой-либо loopback-порт.
- Общая сборка run HOME задаёт XDG/CFFIXED_USER_HOME и run-local TMPDIR.
  Login сохраняется ссылкой `Library/Keychains` по BE-22/24; личный `.cursor`
  не копируется. Диагностический `--runner` остаётся явным тестовым запуском.
  Linux headless поддержка сохраняется, Seatbelt на Linux не объявляется.

## Файлы, сеть и границы

Запись по умолчанию закрыта. Разрешены клон, отдельный scratch, наблюдавшиеся
в BE-22 service paths: три JSON состояния `.cursor`, chats/projects/ai-tracking,
managed/plugins/cache/skills-cursor, compile cache, run-local `.local/bin` и
`.local/share/cursor-agent/versions`. Около выбранного executable разрешён
только `.running`, а не весь каталог установки. HOME целиком не разрешается;
run git shim и личный MCP-конфиг остаются вне writable paths. Служебные каталоги
создаёт демон до spawn. Параметры передаются массивом argv без shell interpolation.

Git objects/index/refs/logs/HEAD доступны. В клоне запрещена запись в
`.git/config`, `.git/hooks`, `.git/info` и `.kaban`; переименование `.git` целиком
также закрыто. Основной репозиторий имеет отдельный deny. Остальные данные
`Application Support/Kaban` закрыты отсутствием write allow: выделенные клоны,
run HOME и scratch внутри `Workspaces` являются необходимыми исключениями,
а DB, journal, logs других runs и родительские каталоги исключениями не являются.
Личный `.gitconfig` закрыт. Чтение `.ssh` и Cursor globalStorage запрещено
по **реальному** HOME. Пути канонизируются `realpath`: Foundation на macOS может
сократить `/private/var` до `/var`, что ломает kernel path match.

Для task run loopback разрешён только на порт `MCPHostEndpoint`, общий для
`/mcp` и `/git/check`; второй слушающий порт недоступен. Внешний IP-трафик
разрешён: host allowlist и proxy находятся вне MVP по принятой архитектуре.
Unix worker socket разрешён только в `.cursor/projects` run и scratch;
DNS использует системный Unix socket mDNSResponder. Сигналы доступны только
процессам той же песочницы. Mach lookups ограничены login/trust/preferences/
resolver службами, необходимыми CLI и compiled shim.

## Что остаётся открытым

**Изоляция токена CLI не гарантирована.** CLI и его потомки наследуют один
профиль; доступ к login Keychain сохраняется. Это принятый остаточный риск
архитектуры §13, не обещание credential isolation.

- Платный `-p` с настоящим агентом, commit в standard и зелёными гейтами под
  профилем не выполнен. Бюджет BE-22 исчерпан (2/2); нового платного запуска нет.
- Список BE-22 получен из surviving файлов; fs_usage не подтвердил полную
  трассировку. Краткоживущие файлы, все runtime компоненты/автообновления и
  полнота каталога записей остаются непроверенными. Профиль не расширяется
  разрешением всего HOME при первом отказе.
- Типичные сборки (`swift build`, `npm ci`), полный список их кэшей, сетевой
  allowlist и разделение CLI/tools по разным профилям относятся к BE-29.
- Installed LaunchAgent/XPC, системные permissions, reboot и полный UC-22/MVP
  не приняты. `status`/`mcp list`, синтетический Cursor и App build их не заменяют.
- Discovery/status/catalog и MCP preflight остаются отдельными наблюдательными
  CLI-вызовами до запуска модели. Seatbelt применяется к task/model probe `-p`;
  отдельная бесплатная проба дополнительно проверяет observational команды под ним.
