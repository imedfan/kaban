## Реализация

В настоящем `ProjectLifecycleSheet` между папкой и шаблоном появился нативный
picker локальной базовой ветки. `main` выбирается только при наличии в ответе;
без неё выбор обязателен. Подсказка «i»: «От этой ветки создаются ветки задач,
в неё же вливается результат». Длинные имена остаются точными в состоянии,
контрол ограничивает отображение доступной шириной. Настройки проекта показывают
`ProjectSummary.baseBranch` без кнопки смены.

`ProjectLifecycleStore` сохраняет выбор с path/template/identity, восстанавливает
его из pending envelope и блокирует новую отправку до correlated event либо
подтверждённого snapshot. Поздние reads предыдущего пути/формы/session и ответы
с чужим commandId отбрасываются. Обновление списка не меняет явный выбор.
Отказ `base_branch_missing` находится у поля; текст берётся из русского шаблона
с `params.branch`. Исправление выбора снимает старую ошибку поля и сохраняет
остальной ввод. Пустой репозиторий и ошибки чтения блокируют добавление.

**Уточнение контракта.** В принятой BE-31 `listBranches(projectId)` требует уже
зарегистрированный проект — использовать его до `addProject` невозможно.
Добавлен отдельный read-only `listBranchesAtPath(path)` с собственной capability.
Старый запрос и обязательный `projectId` не изменены. Новый запрос работает без
`main` и первого коммита, не создаёт проект/journal/receipt; повтор остаётся свежим.
Используется существующий bounded git runner без hooks/filters/shell; validation
пути общая с `LocalGitRepository`, проверка базы при add не ослаблена. Из списка
исключены remote refs; одинаковый tag не добавляет префикс `heads/` к имени ветки.
Старая служба получает предложение обновиться, без выдуманного списка веток.

## Повторение

```sh
KABAN_SCENARIOS=Scenarios/M1 swift test
KABAN_SCENARIOS=Scenarios/M1 swift test --filter 'ProjectLifecycleStoreTests|ProjectLifecycleTests|Team2CompatTests|Team2ReferenceSamplesTests'
xcodebuild -project Kaban.xcodeproj -scheme Kaban \
  -destination 'generic/platform=macOS' -derivedDataPath /tmp/kaban-fe27-app \
  ONLY_ACTIVE_ARCH=YES CODE_SIGNING_ALLOWED=NO build
python3 tools/check-project-context.py
```

Для native smoke создать **новый** каталог `/tmp/kaban-fe27-<suffix>/repository`,
`git init -b master`, настроить git identity, сделать первый commit и создать
ветки `vanished` и `release/very-long-local-base-branch-name-for-minimum-window-layout`.
Затем запустить Debug executable:

```sh
/tmp/kaban-fe27-app/Build/Products/Debug/Kaban.app/Contents/MacOS/Kaban \
  --developer --developer-database /tmp/kaban-fe27-<suffix>/state.sqlite \
  --project-smoke /tmp/kaban-fe27-<suffix>/result.json \
  --project-smoke-base-branch YES \
  --project-smoke-repository /tmp/kaban-fe27-<suffix>/repository \
  --qa-theme dark --qa-size minimum \
  --export-live-window /tmp/kaban-fe27-<suffix>/window.png
```

Smoke удаляет только `vanished` внутри указанного private repo. Повторять с новой
БД/папкой. Для empty: `git init` без commit и `--qa-base-mode empty`; для non-git:
пустая папка без `.git` и `--qa-base-mode non-git`. Системная служба не регистрируется.
