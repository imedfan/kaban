## Реализованное поведение

Human Review открывает «Сводку»: резюме стадий в общей таблице, diffstat,
полные SHA/subjects коммитов, раскрываемый gate output и ссылки к источникам
и логам runs. Текст неизвестного формата остаётся читаемым и доступным целиком;
крупный материал открывается в существующем native readonly source sheet.
Пустые материалы/clonePath, SHA, counts, стоимость и token usage явно неизвестны.
Renderer не считает знаки из масштабированного git --stat точными additions/deletions.
Факт предыдущего merge conflict берётся из bounceByReason; отдельный conflict
resolution diff не выдумывается.

В постоянном footer — Cursor, возврат, отклонение и одобрение; edit/priority
и общие task controls сохранены в меню. Cursor открывает проверенную директорию
из actual TaskDetail.clonePath через NSWorkspace, с inline отказом при недоступности.
Одобрение отправляет typed approve и переводит карточку только по correlated
event в следующую очередь; `.ok` сохраняет pending, локальный Done не выставляется.

HumanReviewStore сохраняет exact комментарий вместе с просмотренными card,
pipeline и material context. Возврат всегда передаёт явную writable agent target,
которая предшествует review по on_success, независимо от display order.
Default поступает от backend: nil не восстанавливается локально, возврат
недоступен, ссылка открывает актуальные pipeline issues в настройках проекта.
Редактор pipeline остаётся FE-13. Отклонение позволяет выбранную допустимую
стадию без комментария либо отмену с keepBranch=false по умолчанию; форма
объясняет архив последнего коммита и отсутствие незакоммиченных правок в нём.

CommandId сохраняется до send через существующий BoardSession/journal.
Pending блокирует повторное решение; потерянный reply повторяет exact envelope.
Invalid_state перечитывает details и оставляет комментарий inline. Изменённый
результат требует явного повторного просмотра перед использованием draft;
закрытие/перезапуск/разрыв связи не теряют текст. Нечитаемое storage не перезаписывается.
Единая native ⌘↩ отправляет ответ FE-10 или одобряет актуальное review; за decision
sheet, прочими sheets/онбордингом и при pending она недоступна.

Найден и исправлен backend дефект: requestChanges передавал humanComments
агенту, но не сохранял комментарий в TaskDetail.feed. Теперь review_comment
с redaction записывается в одной транзакции со state/journal/outbox, только
после применённого решения. Replay не дублирует запись; отказ не добавляет её.
Это не humanAnswered и не ответ на outstanding question. Mock использует те же
typed команды/events, target guards, очередь, счётчики и вид записи ленты.

## Границы и следующая работа

Это NSWindow/NSView layout captures actual WindowGroup, не ReferenceFrameView
и не системный compositor. Native NSTextView/menu проверяют binding/routing;
физическая клавиатура, pointer/scroll, VoiceOver, OS focus и installed signed
XPC/helper остаются в полной FE-22 приёмке.

LaunchServices в изолированном private live режиме подавляла автоматическое
окно. Live QA явно открывает тот же WindowGroup через native openWindow command,
доступную только с `--review-live-smoke`. Production startup не менялся;
автоматический первый запуск normal/installed App этим прогоном не подтверждён.

Открытие Cursor проверено для реального временного clonePath. Agent Cursor CLI,
session resume, MCP и следующий запуск после возврата не запускались.
Стоимость/usage, точные per-file +/− и отдельный conflict-resolution diff
[не переданы бэкендом](frontend-backend-integration-gaps.md#fe-11-материалы-ревью).
Неизвестность показана явно, требования не сокращены. Approve проверен до
merge queue; actual merge/conflicts/recovery — следующая отдельная FE-12
после принятия FE-11. Полный M1/MVP не принят.
