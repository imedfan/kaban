## Что реализовано и решения

- Явные durable projects/settings/body/detail, additive v2 migration, стабильные
  effect IDs command/index, receipts команд/ticks/results, query Snapshot/TaskDetail.
- FakeDriver и атомарная симуляция результата вместе с переходом, audit и ack.
  Известные git/lifecycle effects только симулируются; внешних side effects нет.
  Unsupported/future payloads не подтверждаются, legacy batch ack запрещён managed tasks.
- Scheduler делает одно действие на tick; сохраняет weighted cursor, учитывает
  приоритеты/FIFO, WIP и общий/проектный потолки. Human admission marker держит
  место до stage exit/final, включая паузу после допуска.
- Optional pausedState сохраняет происхождение pause. Resume из явного review
  возвращает review; неизвестная legacy pause возвращается в queued.
- Cancel/pause/recovery supersede старые execution effects, сохраняя нужные
  kill/rollback/cleanup. Legacy pipeline mismatch выдаёт incompleteProjection.
- Четырёхстадийный fake fixture имеет только локальное исключение merge_count.
  Общий production-валидатор не менялся; summary честно остаётся isValid=false
  с соответствующей issue. Этот fixture не выдаётся за production pipeline.
- Frontend хранит точный Markdown body: nil означает неизвестность, известная
  пустая строка редактируется. Создание ждёт correlated taskCreated, детали
  защищены от чужого task ID и устаревших generation/seq. Snapshot gaps сверяют
  набор доски и выбор. Отказы сохраняют ввод; receiver перепроверяет перенос.

## Что не сделано и найденные ограничения

HC12 остаётся частичным: stage/human WIP shrink нельзя проверить через API
неизменяемого pipeline. HC17 pruning/retention API ещё отсутствует. HC11
retry reservation/no-doublecount и HC13 returned/custom priority ordering
не имеют отдельной managed integration проверки; соответствующий код не
объявляется полностью принятой матрицей. HC09 неверные стадии human commands
покрывает существующий reducer, без новых transactional assertions.

XPC, daemon executable/registration, kabanctl, real Cursor/git/MCP/gates,
quota и внешний claim/lease worker впереди. Подпись и полная визуальная/
доступностная приёмка, dark tokens, DnD, остальные frontend экраны не завершены.
Новые production issues не оставлены без решения: находки ревью исправлены
в этом PR и закреплены регрессиями. Полного exactly-once внешних процессов нет.

## Документы и Drive

Планы backend/frontend, журнал решений, архитектура и контракт обновлены в Git.
Перед записью проверены полные исходники четырёх Drive-файлов по SHA-256:
они совпали с предыдущим manifest. Первая попытка update архитектуры вернула
Google 403 ACCESS_TOKEN_SCOPE_INSUFFICIENT; новые изменения этой сессии в Drive
не опубликованы. Это недостаток OAuth scopes подключения, не конфликт прав
конкретного файла. Требуется переподключить Google Drive с доступом на запись,
затем повторить сверку и публикацию. Прежний manifest исторический; текущий
статус указан в m1-drive-publication-2026-10-04.json. Подключение/права не меняли.

## Как проверить и следующий шаг

В объединённом checkout:

```sh
KABAN_SCENARIOS=Scenarios/M1 swift test
xcodebuild -project Kaban.xcodeproj -scheme Kaban \
  -destination 'generic/platform=macOS' \
  -derivedDataPath /private/tmp/kaban-m1-combined-derived \
  ONLY_ACTIVE_ARCH=YES CODE_SIGNING_ALLOWED=NO build
open /private/tmp/kaban-m1-combined-derived/Build/Products/Debug/Kaban.app
```

На доске выбрать проект, создать задачу с описанием/критериями, открыть детали,
изменить Markdown, перенести назад с подтверждением, отменить задачу с выбором
сохранения ветки. Данные демо-клиента в памяти; перезапуск не сохраняет задачи.
Полную визуальную приёмку этот запуск не заменяет.

Следующий инкремент: XPC adapter и соединение приложения с проверенным ядром;
затем live runner/git/MCP и целевые isolation-спайки. Продуктовых решений,
блокирующих текущий инкремент, к пользователю не осталось; Drive publication
зависит от восстановленного write scope.
