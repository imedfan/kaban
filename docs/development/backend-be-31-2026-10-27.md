## Поведение

- `addProject(..., baseBranch?)` принимает существующую локальную ветку.
  Отсутствие поля или null оставляет `main`; неверное имя, tag и remote-only
  ref дают `base_branch_missing` с точным `params.branch`, без проекта и шаблона.
  Отказ сохраняется для replay commandId.
- Используется уже существующее durable поле `ProjectSummary.baseBranch`.
  Reopen/relink сохраняют выбранную базу; команды её изменения нет.
- Источник конфигурации — `refs/heads/<base>:.kaban/`: pipeline, skills,
  source hash, gates detection, refresh/recheck и draft apply.
  Шаблон/YAML коммитятся в выбранную базу только при её checkout;
  чужой checkout остаётся на месте, source read отличает committed от working.
- Клон явно импортирует выбранный local ref в `refs/kaban/base` перед созданием
  ветки задачи. Это работает и при другом checkout origin, когда обычный clone
  создаёт локальной только текущую ветку. Merge временно импортирует ту же базу,
  делает rebase и fast-forward. При другом checkout origin обновляется только
  выбранный ref с compare-and-swap; index и working files не меняются.
- Восстановление `.cursor/mcp.json`, protection/result check, принятие
  легитимного сдвига базы при merge, `merge_result.ref` и recovery после
  fast-forward адресуют выбранную ветку. Восстановление BE-26 перед result
  check сохранено.
- `/git/check` защищает выбранную базу в checkout/switch/rebase и целевых
  notes/fetch/worktree; denial хранит hard invariant, который нельзя обойти
  `allowGitOnce` или изменением политики.

## Границы

FE-27 (picker базы и inline branch refusal) остаётся отдельной задачей.
В App/BoardCore изменены только pattern matches новой arity команды;
сценарий подключения через native picker здесь не реализован.
Существующий `listBranches(projectId)` адресует уже подключённый проект;
для pre-add списка по выбранному пути FE-27 потребуется согласовать query-контракт.
Смена базы подключённого проекта и несколько баз вне MVP.

В архитектуре §5 сказано `ProjectSummary.baseBranch=nil` у старого демона,
но уже принятый v1 DTO и legacy fixtures требуют String. Это существующее
расхождение: BE-31 сохраняет обязательность старого поля, как предписывает
AGENTS.md, и не подставляет выдуманную базу при decoding snapshot.

Платный Cursor, installed helper и системная регистрация не использовались.
Store/daemon tests используют реальные disposable Git-репозитории и SQLite,
но completion агента задаётся детерминированно. Полный M1/MVP не принят.
