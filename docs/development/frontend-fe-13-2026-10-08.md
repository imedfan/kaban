# FE-13: нативный редактор и безопасное применение pipeline

8 октября 2026. Ветка `codex/fe-13-pipeline-editor` от проверенного после fetch
main `6aac109` — принятой FE-12, [PR #103](https://github.com/imedfan/kaban/pull/103).
Проверки относятся к коду `18239fa`, включая native source recovery после
catch-up, project switching и ограничение длинного заголовка. Среда: macOS,
arm64, полный Xcode, App собрана с CODE_SIGNING_ALLOWED=NO.

## Поведение

В настройках проекта открыт настоящий SwiftUI editor. Список стадий, basic/display,
executor, transitions, retry/timeouts, hooks, git, workspace и board limits
редактируют один draft. Форма меняет адресованные диапазоны исходного YAML;
комментарии, CRLF, Unicode и неизвестные поля не пересериализуются. Stage display
order не меняет on_success. Стадию можно добавить или удалить; занятая стадия
защищена UI и окончательно проверяется backend.

Для anchors, tags, неоднозначных/сложных конструкций доступен точный YAML.
Существующие return targets имеют поля stage/limit; добавление/удаление целей,
многострочные sequences и agent.env доступны в YAML. Эти способы используют
те же validate/apply. Model ID вводится явно, MCP пока доступен как исходное поле;
их каталоги/pickers — FE-14/16. Полный policy table/reset UI — FE-15.

Каждый projectId имеет отдельный PipelineEditorStore на время жизни BoardStore.
Смена проекта сохраняет неотправленный ввод и меняет владельца ⌘↩. После restart
source загружается из применённого файла; неподанный draft не сохраняется между
запусками. Чтение автоматически повторяется после восстановления связи, если
редактор открылся во время catch-up.

Валидация идёт только через службу с debounce 300 мс. Поздний ответ проверяется
по generation/session, project, contentHash и обеим базовым identity. Ошибки
блокируют apply, warnings разрешают. Поля и стадии получают path/stageId/severity;
перевод использует server params, неизвестный код/неполные params — backend message.
Resolved policy/targets/WIP получены от службы, клиент не вычисляет их из YAML.

## Source и apply

`getPipelineSource` читает свежие committed и working UTF-8, path, valid nullable
baseVersionHash, baseSourceHash и worktreeSourceHash. Nil означает отсутствующий
файл, пустая строка — существующий пустой. Query не создаёт receipt или journal.
Source включает identity assets .kaban/, а contentHash — только точный YAML.

Editor перед apply повторно читает source. Изменённый файл/база показываются рядом
с черновиком: recheck сохраняет ввод, новая база выбирается явно, reload заменяет
ввод только с подтверждением. NSFileCoordinator, descriptor-relative O_NOFOLLOW,
проверки exact bytes до и после временной записи и atomic rename/link защищают
запись. Symlink/специальный файл и отдельная внешняя правка дают отказ.

Native draft добавляет optional requiresExactWorkingContent=true. Backend требует
уже записанный YAML до подготовки Git commit; старый BE-03 draft без флага
сохраняет прежнее поведение. Required nullable поля DTO не ослаблены.
Повторный commandId не создаёт второй commit. UI не коммитит самостоятельно.

Update передаётся через BoardSession и общий command journal. Ответ `.ok` сам по
себе не отмечает версию применённой; нужна correlated pipelineApplied или покрывающий
её snapshot. Более поздний draft не становится сохранённым от старого apply.
Отказ не откатывает файл: draft, неприменённые байты и последующий внешний edit
сохраняются. Ошибка и новое source остаются доступны для сравнения.

## Критерии и доказательства

| Критерий FE-13 | Проверка | Результат |
|---|---|---|
| Errors блокируют, warnings разрешают; model/Auto/return валидирует daemon | PipelineEditorTests; PipelineLifecycleTests invalid drafts; native malformed/Auto/warning | Passed; warning-only exact source применён |
| Чужой project/base/hash, race и malformed сохраняют ввод | Editor delayed replies; protocol required fields; lifecycle hash/skill race; native external write | Passed; нет устаревшего apply |
| Comments/unknown fields сохраняются, сложный YAML не переписывается | Exact text comparisons для block/flow/CRLF/Unicode/anchors/duplicate; native NSTextField | Passed; committed bytes совпали с draft |
| Busy stage не удаляется, WIP/model/policy authoritative | PipelineLifecycleTests run freeze/stage removal/WIP shrink; resolver suites; native WIP=1 | Passed; старые runs сохраняют spec, snapshot имеет новый лимит |
| Write/refusal сохраняют поздний edit; version согласована с snapshot | Writer/refusal tests; strict native contract; real apply и daemon restart | Passed; один commit, exact source/version/WIP подтверждены |

Полный `KABAN_SCENARIOS=Scenarios/M1 swift test --disable-sandbox` прошёл: 632 tests,
0 failures (Transport 29, Protocol 68, Kit 180, DaemonCore 180, BoardCore 175).
После последней правки BoardCore повторно прошли 272 tests клиентских suites.
Последующие правки App проверены отдельной финальной xcodebuild сборкой и native
матрицей. Context checker и git diff --check прошли.

В shell sandbox NSFileCoordinator получал Cocoa error 512; проверка выполнена
с разрешённым запуском вне shell sandbox. Тесты/права приложения не ослаблялись.
Один новый lifecycle test первоначально неверно ожидал `.ok`; реальный контракт
возвращает `.pipelineVersion(hash:)`, ожидание исправлено и полный прогон повторён.
Native повторы выявили и исправили identity владельца при смене проекта,
расхождение selected project, переполнение длинного header и ранний source read
во время catch-up. Финальные восемь запусков прошли.

CI исходного `4e412c8` выявил несовместимость `isolated deinit` со Swift 6.1:
[Linux job](https://github.com/imedfan/kaban/actions/runs/37789131376/job/113351500881)
требовал экспериментальный IsolatedDeinit. В PipelineEditorStore использован
обычный deinit с той же отменой debounce Task, как в RunLogStore; версия Swift
и CI flags не менялись. Linux build на локальном `swift:6.1` с SQLite headers,
восемь editor tests на macOS и отдельная unsigned App build прошли.

## Настоящие окна

`tools/check-pipeline-editor.py` создаёт private Git repositories и БД, запускает
реальный daemon через developer stdio и настоящий WindowGroup. Native NSTextField
и его field editor изменили имя; меню ⌘↩ применило draft, после restart файл и
snapshot совпали. Имитация использована только в детерминированных тестах состояния.
Ни Cursor CLI, ни регистрация системного helper не запускались.

Композиция следует stage settings v0.2.1 из [design/README](../../design/README.md):
навигация стадий, секции, карточки и одна кнопка применения, native controls и
существующие tokens. Проверены светлая/тёмная тема, 1040×640, long name, YAML,
повреждённый и отсутствующий файл. Низ форм прокручивается, длинный header имеет
две строки и tooltip полного имени.

## Границы

AppKit capture подтверждает настоящее окно; системный compositor, физические
keyboard/pointer сценарии и VoiceOver не проверены. Signed installed App/helper
permissions/bookmarks после restart и живой Cursor/MCP остаются системной приёмкой.
FE-14/15/16 должны расширить существующий draft, не создавать отдельный save.
Все пять checkbox FE-13 относятся к описанным Core/native/private daemon проверкам;
полная приёмка FE-22 и весь M1/MVP остаются открыты.
