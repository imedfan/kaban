6 октября 2026. База после fetch — main `db9f73a` (FE-01 / PR #92 принят).
Рабочая ветка — `codex/fe-02-session-recovery`. Этот отчёт описывает FE-02;

## Пользовательский результат

BoardStore владеет одной отменяемой сессией BoardSession; время жизни подписки
не зависит от открытых деталей и remount окна. Во время connecting,
synchronizing и reconnecting новые действия заблокированы. Ошибка подключения
имеет отдельное состояние и кнопку повторной проверки. Gap, окончание потока и
overflow создают новую подписку с полной синхронизацией; повторный retry сначала
дожидается завершения прежней сессии.

Replacement заменяет durable и volatile state. Journal seq, принятый ephemeral
cursor и применённый cursor разделены; afterSeq удерживает volatile update до
barrier. Старые флаги и старый replacement не откатывают более свежие значения.
Непрерывность wire-offset проверяет DaemonClient: его session poller может
отфильтровать stale flags, поэтому delivered offsets могут иметь пропуск.
Смена incarnation инвалидирует прежние reads/reconciliation.

Точный envelope записывается до отправки. После reopen/reconnect проверяется тот
же commandId и payload. Обычная мутация завершается своим typed event/resource
либо receipt, покрытым применённым authoritative snapshot; `.ok` сама карточку
не меняет. Pending scopes task/project/global/pipeline/grant/denial/model
разделены. Event-before-reply и поздняя ошибка транспорта не оставляют ложное
«Отправлено». Неизвестная доставка, ожидание события/effect и отказ различаются.
Старый backend, не поддерживающий сохранённое действие, не превращает неизвестный
исход в новый отказ: команда сохраняется, reconnect показывает причину.

Create после retention выбирает существующую карточку из snapshot с ID из
сохранённого receipt. Старое создание не закрывает форму другого проекта или
новый сохранённый ввод. Detail response защищён ID, generation, session epoch и
seq; удаление карточки закрывает прежний выбор, более старый ответ не заменяет
актуальный body. Burst refreshes объединяются в один текущий и один свежий read.
Обычный resync/selection инвалидирует результат без отмены общего stdio RPC:
его транспортная отмена могла остановить helper, поэтому её оставляем lifecycle.

Create/edit drafts хранятся отдельно, с namespace выбранного источника. Reconnect
их не отправляет. Форму можно закрыть во время pending и открыть снова. Markdown
сохраняется буквально; nil body остаётся неизвестным. Подтверждение title-only
не удаляет неотправленное описание. Saved baseCard не позволяет незаметно
перезаписать изменившуюся задачу; пользователь может сверить/удалить черновик.
Это обычная persistence через KeyValueStoring/UserDefaults, без обещания fsync
при внезапном отключении питания.

## Контракт исхода WIP

До FE-02 acceptance receipt restoreWIP сохранялся до исполнения git и после
retention не доказывал терминальный исход. TaskDetail теперь имеет optional
`wipRestoreOperations`: nil означает неизвестность legacy source, [] — отсутствие
intents. Записи содержат commandId/runId/ref и pending/succeeded/failed/superseded.
Success/failure имеют completedSeq; failure text проходит SecretText.redact.

Store читает существующий effect/receipt в том же read transaction, что TaskDetail
и его seq. Схема БД, эффект, claim и execution не меняются. Pending/claimed не
выдаются за запуск git. После retention/reopen сохраняются исходы разных
восстановлений одного run. Клиент не разбирает приватные IDs/тексты feed и не
завершает restore на `.ok`, taskUpdated или простом snapshot.
Legacy JSON по-прежнему декодируется, все прежние required fields обязательны.
Неподдерживающий outcome source сохраняет неизвестность; огромные детали дают
прежний явный detail_too_large, без скрытого обрезания истории.

Вызовы fixture create/edit/move/cancel/pause/resume и поиск дошли до keyboard
этапа native smoke. Локальная macOS не дала окну focus; keyboard assertions не
ослаблены. Native live smoke с embedded daemon в нескольких запусках не получил
WindowGroup (`runtime=nil, windows=[]`). Контрольный сохранённый bundle FE-01 дал
тот же отказ; новая панель runtime error и fixture окна открываются. Это не
подтверждение live App-пути на финальном HEAD. Его нужно повторить в среде,
где WindowGroup создаётся; CI keyboard smoke остаётся обязательным доказательством.

AppKit layout capture не подтверждает системный compositor, ручной pointer и
VoiceOver. Штатный установленный Mach XPC всё ещё зависит от BE-20. Платный
Cursor и системная регистрация не выполнялись. FE-03–22 и полный MVP остаются
отдельной работой. Материалы дизайнера для recovery/pending перечислены в
[отдельном файле](frontend-design-gaps.md).
