## Реализованное поведение

История использует getRunHistory и RunSummary, показывает новые запуски сверху,
stage, requested/actual model, endReason, countsTowardLimits, фактические даты,
elapsed завершённого запуска, exitCode, WIP ref и logPath. В inspector 500 pt
кнопки лога/WIP стоят перед metadata; длинные поля ограничены строками с полным
help/copy, вся запись доступна отдельным readonly источником. Исходная композиция
03-task-details, четыре вкладки, footer и прежние tokens сохранены.

RunSummary.number — порядковый запуск задачи, поэтому подписан «запуск №».
Текущий TaskCard.attempt/maxAttempts показывается отдельно. Исторические attempt
и stage_entry отсутствуют в wire DTO; UI явно показывает неизвестность.
[Конкретный пробел источника](frontend-backend-integration-gaps.md#fe-09-историческая-попытка-и-заход-в-стадию)
оставляет полное требование FE-09 открытым.

RunLogStore принадлежит BoardStore и использует тот же KabanClient.
BoardSession остаётся единственным владельцем application updates.
Read/tail сохраняют daemon offsets, проверяют ownership, непрерывность, размер
и диапазон страницы; overlap дедуплицируется, изменённый payload и пропуски
дают отказ без продвижения cursor. Reconnect продолжает последний полученный
offset. Поздние reads и tail предыдущего run/невидимого sheet игнорируются.

Память payload ограничена 50 000 записей, 50 000 строк и 8 MiB.
Одна запись свыше 256 KiB или 5 000 строк оставляет placeholder с исходным offset,
типом и размерами; полное очищенное событие читается отдельно по явному действию.
Encoding, подсчёт строк и форматирование выполняются вне UI actor.
Завершённый backlog читается последовательными readLog страницами с backpressure;
живой лог использует tailLog. Так native layout не переполняет bounded transport
queue и чтение не компенсирует нагрузку пропуском записей.

Лог — readonly/selectable native TextKit2, с Cmd-F, copy, раскрытием tool output,
ранними страницами и явным переходом к последним. Удалённый prefix требует
«Читать доступное» и не перенумеровывается; неизвестный prefix, пустой лог,
unavailable и разрыв связи имеют отдельные состояния. EOF сам не доказывает
завершение. Просмотр истории приостанавливает tail. Смена run, закрытие sheet
и переход к полному источнику прекращают прежний tail. Новые записи сохраняют
позицию и выделение по offset даже при удалении старого prefix; автопрокрутка
работает только у нижнего края либо по явному переходу.

Полный источник крупной записи — exact Codable JSON в отдельном native sheet.
TextKit2 добавляет его частями, сохраняя Unicode, поиск и readonly selection.
Экспорт сохраняет только загруженные нормализованные AgentEvents и исходные offsets;
крупные записи, не помещённые в cache, явно исключены. Raw log не участвует в
экспорте. Кнопка сырого лога запрашивает NSOpenPanel grant для точного серверного
logPath, проверяет выбранный файл и readable access перед NSWorkspace.open.
Сам path не даёт права читать файл.

WIP confirmation фиксирует точные task/run/ref/pipeline и session generation.
Разрешены только поддержанные agent-состояния и актуальная история без pending
task command. UI объясняет восстановление дерева/index клона и резервирование
текущих правок. Typed restoreWIP идёт через BoardSession; App не выполняет git restore.
Ответ .ok оставляет awaitingEffect. Correlated outcome подтверждает результат
и перечитывает detail/history; failure/rejection/superseded имеют честный статус.

## Границы приёмки

Исторические attempt/stage entry требуют расширения backend DTO/producers;
полное требование не заменяется номером запуска. Нормализованный экспорт и
permission guards проверены кодом/native scenario, но ручной выбор raw file,
его открытие внешним приложением и сохранение FileExporter через системный
диалог не пройдены. Ручные pointer/физические клавиши/Tab/VoiceOver, скрытие или
минимизация системного окна, installed signed helper/XPC/reboot и живой Cursor
не проверены. In-process native Enter/Escape не заменяют физическую клавиатуру.

Четыре критерия FE-09 отмечены в границах выполненных Core/native/private daemon
проверок. Исторические metadata, системные permissions и общая FE-22 приёмка
остаются открытыми. Следующая отдельная задача — FE-10.
