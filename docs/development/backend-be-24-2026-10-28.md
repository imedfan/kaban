## Изменение поведения

Обычный daemon host использует сохранённый executable из BE-23 без `--runner`.
Первый process pass только наблюдает/останавливает процессы, затем runtime
выполняет эффекты, scheduler и clone preparation. Последний process pass
запускает Cursor только при наличии MCP host и готового клона.
Явный `--runner` сохраняет diagnostic-семантику без Cursor argv.

`CursorLaunch.plan` получает модель из durable `AgentRunRequest`, включая
приоритет task override над моделью стадии. Пустая модель, `auto` и placeholder
отвергаются до создания дочернего процесса. Аргументы: `-p --output-format
stream-json --model <id> --trust --approve-mcps`, затем `--force` только write
и промпт одним аргументом. `--approve-mcps` разрешён после успешного exact-set
preflight; без него общий planner approval не добавляет. Подтверждённого session id
в production пока нет: `resumeRequested` не выдумывает `--resume`.

RunSpec совместимо сохраняет optional `promptParts`: skill из committed pipeline
asset snapshot (включая referencedSkills), title/body и handoff summary с последними
материалами diffstat/gate_output соответствующей стадии. Запуск добавляет frozen
request additions: gate output, human answer/comments, return issues, finish reminder,
merge conflict и read-only violation. Промпт требует финальный MCP-вызов и
периодический report_progress. Полный diff доступен через клон; сохранённый
материал diff в промпте — существующий diffstat, новый producer полного diff не добавлен.
Legacy RunSpec декодируется без promptParts; freezeRunSpec допускает отсутствие legacy task_detail
и сохраняет pipeline snapshot без выдуманного prompt context. Полный запуск
старых production rows без деталей этим не расширяется.

Действующие, не потраченные/отозванные/истёкшие grants текущей стадии читаются
перед запуском и входят в `git_grants`. Process record, durable delivery и
`GitGrantDelivered(next_prompt)` записываются одной транзакцией до exec-gate.
Повтор pass не создаёт второй process/delivery; доставка grant не расходует.
Сбой записи журнала закрывает gate и останавливает launcher.
Crash между commit и открытием gate может предотвратить фактический запуск:
это не exactly-once подтверждение прочтения промпта агентом.

## HOME и совместимость CLI

По поручению Артёма выбрать рабочий вариант принят подтверждённый BE-22 HOME:
на macOS `Library/Keychains` ссылается на каталог пользователя. Личный `.cursor`
не копируется. HOME/CFFIXED_USER_HOME/XDG config/cache/data направлены в каталог
run; CURSOR_CONFIG_DIR из окружения удаляется. Ссылка не изолирует credentials:
Seatbelt и граница токена остаются BE-28/29. Вариант API key не потребовался.

Для совместимости принятой BE-22 добавлены JSON `status --format json` и
наблюдаемый MCP listing `name: not loaded (needs approval)`. Старые текстовые
status/tab fixtures сохранены; неизвестный listing блокирует старт.
Это не правка stream parser/classifier из BE-25.

Бесплатная повторная проверка реального CLI `2026.09.23-86fc751`:
`--version`, `status --format json`, `mcp list` завершились с exit 0,
`isAuthenticated=true`, listing содержит только `kaban`. Личный MCP-файл
существует в обычном HOME и отсутствует в run HOME. Проверка выполнена с теми же
HOME/XDG переменными; модель не запускалась. Локальный результат:
`/tmp/kaban-be24-free-7tiika3q/facts.json` (HOME/Keychain не публикуются).

## Открытая приёмка

- Новый платный `-p` из production `--launch-agent` не выполнялся. Бюджет BE-22
  был 2/2; он не расширяется этой задачей. Нужен отдельный разрешённый live-прогон.
- Бесплатные status/MCP и синтетический daemon не доказывают installed helper,
  reboot, платный MCP-вызов production-доски или полную read-only изоляцию.
- Production stream/parser/model/limit fixtures — BE-25; Seatbelt — BE-28;
  credential/tool boundary — BE-29. Полный MVP не принят.
- Native smoke проверяет настоящее окно и базовые typed actions; light/dark,
  минимальные размеры и installed UI в этой backend-задаче заново не принимались.
