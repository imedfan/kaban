# Следующий инкремент M1: fake pipeline и действия доски

2026-10-04. База: main `4303550`, PR #62 принят. Все новые PR направляются
в main. Пользователь принимает PR; команда не мержит. Субагенты:
Architect/Analyst, Backend и Frontend — gpt-6.1-sol medium.
Дизайнерские работы и редизайн исключены.

## Backend

Управляемый фиксированный fake fixture queue → agent → human → terminal.
Узкое внутреннее исключение merge_count допускается только этому fixture;
production-валидатор требует merge, и summary сохраняет эту ошибку.
Явные проекты, настройки, Markdown body и история задачи сохраняются в БД.
Snapshot/TaskDetail читают согласованную durable проекцию; неизвестные legacy
данные не подменяются продуктовыми defaults.

Отдельный fake worker обрабатывает effects со стабильными ID. Результат,
reducer transition, detail/journal и ack фиксируются одной транзакцией.
Известные файловые/git действия только симулируются с durable receipt;
реальных процессов, репозиториев и файлов клона этот инкремент не меняет.
Это не гарантия exactly-once внешних процессов.

Scheduler tick сохраняет receipt и fairness cursor; учитывает stage WIP,
общий и проектный потолки, приоритеты/FIFO, weighted fairness и human admission.
Admission marker удерживается до выхода из human-стадии; pause/resume после
допуска не освобождают место. Пауза до допуска места не занимает.

Критерий: создать → fake вопрос → ответ → fake completion → Human Review →
approve → done. Reopen/replay не теряют состояние и не дублируют историю.
Миграция v1 → v2 сохраняет ранее записанные task/outbox payloads.

## Frontend

Создание задачи в выбранном проекте, редактирование доступного текста,
перенос с подтверждением прерывания, отмена с выбором сохранения ветки,
пустые состояния. Команды подтверждаются correlated events; ack сам по себе
не меняет статус. DropRules подсказывает жесты, окончательный отказ приходит
через клиентскую команду.

TaskDetail получает совместимый optional body. nil означает неизвестный текст,
а не пустую строку; редактор не перезаписывает его пустым значением. Критерии
приёмки представлены секцией Markdown внутри существующего Command.body.
Приложение остаётся на mock-клиенте; fake backend ещё не подключён через XPC.
