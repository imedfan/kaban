# FE-06: задачи, точный Markdown, приоритет и поиск

7 октября 2026. Ветка codex/fe-06-task-editor; проверенная база origin/main 366f972 — принятый FE-05, [PR #96](https://github.com/imedfan/kaban/pull/96). Код проверок: 2c863bb. Документ и сохранённые результаты добавляются следующим коммитом без изменения проверенного production-кода.

Создание и редактирование используют BoardSession и сохранённые envelopes. Форма выбирает проект и восстанавливает отдельный черновик каждого проекта. Исходный body редактируется единым Markdown-текстом; переключение в нативный просмотр его не меняет. Кнопка раздела критериев добавляет явный заголовок. Доступность запуска и наличие критериев остаются серверными фактами.

Устаревший черновик сохраняется. Форма показывает текущую карточку и описание, требует явной сверки перед сохранением; running/gating запрещают правку, получатель повторно проверяет состояние. При неизвестном body поле текста недоступно, title-only команда посылает body=nil и сохраняет неотправленный текст. Приоритет — отдельная форма с целым числом из TaskCard; он применяется по taskUpdated и влияет на следующий выбор планировщика.

Поиск читает title/id той же проекции, фильтры сохраняют задачи. При отсутствии совпадений в показанных стадиях есть ясный текст и сброс поиска/фильтра. Cmd-N/F используют существующие команды приложения. .ok оставляет pending до подтверждения; закрытие формы сохраняет ввод и не отменяет отправку.

## Оставшиеся границы

Четыре критерия FE-06 проверены для существующего wire-контракта. F3/UC-02 отдельно требуют первоначальный приоритет при создании: createTask пока принимает только project/title/body, поэтому UI предлагает отдельное setPriority после подтверждённого создания. Атомарный initial priority до первого выбора scheduler не реализован; [конкретное расхождение](frontend-backend-integration-gaps.md). Требования не сокращались.

Не проверены ручная активация project Picker, полный обход Tab/VoiceOver и signed installed helper. Локальный stdio/restart не заменяет системную приёмку BE-20. Полный MVP остаётся открытым. Недостающие кадры и размеры для этих состояний записаны в [отдельный файл дизайнера](frontend-design-gaps.md).
