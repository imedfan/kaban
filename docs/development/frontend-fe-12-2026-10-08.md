# FE-12: очередь merge и подтверждённый локальный результат

8 октября 2026. Ветка `codex/fe-12-merge-progress` от проверенного после fetch
main `11e81d7c9296e70cd5e9435a85ab997bf896b4ba` — принятого
[FE-11 PR #102](https://github.com/imedfan/kaban/pull/102). Все шесть CI jobs
финального FE-11 `e51033d` успешны. Реализация FE-12 и проверки ниже относятся
к коду `5760beacc43fd42d713efa1f8f5ddacb289f0274`; последующие документы и кадры
не меняют его. macOS 27.0.1 (26A434), Apple Swift 6.4, arm64, unsigned App.

## Поведение

Карточки различают очередь слияния, общий этап rebase/гейтов, dirty main,
возврат к исправлению, conflict_limit и Done. Позиция очереди берётся из
сохранённого daemon admission sequence. Вторая задача с повышенным приоритетом
не обгоняет ранее одобренную. Если источник не передал порядок, UI сообщает
об этом; время обновления и priority не используются для выдуманной нумерации.

`mergeBlocked` показывает причину ожидания в дорожке проекта. В деталях головы
есть та же причина и типизированная project recheck с pending/refusal/result.
Фронт не изменяет рабочие файлы, индекс или ветку пользователя для снятия флага.
Демон повторяет проверку и обновляет состояние.

Конфликтные пути и вывод красных merge-гейтов доступны в материалах и ленте.
После возврата видна текущая coding-стадия и необходимость повторного Human Review.
Лимит остаётся на Merge, использует waiting token и уточнение из onConflict.limit.
Возврат с комментарием использует разрешённую бэком цель onConflict, сохранённый
draft и существующий native sheet. Approve и его shortcut на merge-лимите недоступны.
Ручной возврат не увеличивает bounce counters.

Бейдж пересечений открывает список связанных задач. Ссылка показывает скрытый
проект и выбирает нужную задачу; неизвестный/удалённый ID остаётся текстом.
Пересечение не добавляет блокировку или локальный переход. Shortcut и task controls
защищены, пока открыт этот sheet.

Done появляется по состоянию службы. Панель показывает подтверждённые локальные
ref и полный commit из durable merge_result, с копированием SHA. Старое или
неизвестное содержимое остаётся доступным целиком; отсутствие результата явно
отмечено. Remote push не является частью этого сценария.

## Необходимые изменения бэкенда

До FE-12 порядок scheduler зависел от priority даже на Merge, что расходилось
с UC-08. При сортировке merge-кандидатов теперь первым сравнивается queue_seq.
Другие стадии сохраняют прежние правила приоритета.

Добавлено optional TaskCard.mergeQueueSequence. Snapshot, TaskDetail и taskUpdated
получают одно значение из task_admission в согласованном чтении/транзакции.
Required legacy поля не ослаблены. Mock передаёт тот же факт при approve и
сбрасывает его после выхода из merge; повтор того же commandId не переочередит задачу.

При применении mergeConflict, красных merge-гейтов и подтверждённого merged
материалы и лента сохраняются атомарно со state/journal/outbox. Structured payload
передаётся через существующий TaskArtifact.text: merge_conflict — JSON
MergeConflictMaterial; merge_result — JSON LocalMergeResult из сохранённого
merge_intent. Вывод и пути проходят redaction. Результат не реконструируется
из диагностических строк или очищенного журнала.

## Проверки

Полный `KABAN_SCENARIOS=Scenarios/M1 swift test` прошёл: 620 tests без ошибок.
После финальных BoardCore изменений повторно прошли все 167 BoardCore tests;
текущий набор составляет 621 test: Transport 29, Protocol 67, Kit 180,
DaemonCore 178, BoardCore 167. Проверены legacy decoding, неизвестные материалы,
FIFO независимо от priority, красные merge-гейты, конфликтные пути после retention,
финальный ref/commit и startup recovery без второго fast-forward.

App отдельно собрана xcodebuild с CODE_SIGNING_ALLOWED=NO. Context checker и
git diff --check прошли. Native merge smoke прошёл в light/dark: настоящий
WindowGroup при 1040×640, native TextEditor с точным CRLF/emoji, одна decision
с одним commandId, correlated возврат в Dev, отсутствие approve на лимите,
overlap sheet и переход в скрытый проект. Exact transport replay допустим и
не считается вторым пользовательским решением. Human Review, task command
routing и полный TaskDetail/readonly source smoke также прошли. Merge smoke
добавлен в обе native CI matrix configurations.

Private stdio App/daemon использовали реальные временные Git-репозитории,
production scheduler, gates и recovery. `tools/seed-merge.swift` допускает только
новый /tmp/kaban-fe12-* и не запускает Cursor CLI или системную регистрацию.

| Сценарий | Подтверждённый результат |
|---|---|
| Два approve из App, priority второй 99 | До resume main неизменён, очередь first/second. После merge baseCommit второго равен commit первого; конечный main равен commit второго. |
| Dirty main со staged и unstaged правками | Project recheck подтверждён; task остаётся blocked. Байты файла, cached/working diff и main совпадают с исходными. |
| Два конфликта и ручной return | Лимит на Merge, пути shared.txt после retention, native comment sheet, durable review_comment, возврат в Dev и неизменный main. |
| Исправление конфликта | До решения снова Human Review; после approve/resume — Done и SHA фактического main. |
| Crash после fast-forward до DB fact/receipt | Новый daemon восстановил Done и merge_result; main/число commits неизменны, новая UI decision не отправлялась. |
| Красные merge-гейты | Возврат в Dev, bounce counter и сохранённый вывод /usr/bin/false; Done не выставлен. |

## Границы

Отдельные wire-фазы rebase/gates/fast-forward, пересекающиеся с dirty main пути
и live producer overlapsWith не переданы. UI отображает имеющиеся данные;
overlap navigation проверена native DTO fixture, а не производителем реальных
пересечений. Эти технические пробелы перечислены отдельно в
[backend integration gaps](frontend-backend-integration-gaps.md). Недостающие
макеты перечислены в [frontend-design-gaps](frontend-design-gaps.md).

Private QA явно открывает настоящий WindowGroup через opt-in native command,
когда LaunchServices не показывает его автоматически. Normal startup не менялся.
Платный Cursor CLI, installed helper/permissions, физические keyboard/pointer
сценарии, VoiceOver и системный compositor здесь не проверены. Четыре FE-12
checkbox относятся к описанным Core/native/private daemon сценариям; полный
M1/MVP и системная приёмка этим не закрываются. Следующая задача — FE-13.
