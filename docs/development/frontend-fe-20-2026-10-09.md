# FE-20: настройки Мака, флаги и отображение квоты

9 октября 2026. База после fetch `484b78d8098915a65db27639e794527ac1e08122` (FE-19, PR #110).
Финальный source `5c28f6bfccd492df97bed8458daa25e96387976d`, ветка `codex/fe-20-mac-quota`.
Реализована клиентская поверхность. Полная UC-21 приёмка остаётся открытой:
в backend нет production quota poller и статуса его запросов/ошибок.

## Поведение и границы состояния

Экран «Этот Мак» редактирует authoritative ceiling, quota consent/options,
интервал и пороги. Паузы Мака/проектов прекращают новые старты; UI не меняет
карточки текущих runs от одного pause flag. Резервирования, потолок и неизвестное
число подтверждённых процессов показываются отдельно. Модели и правила пулов
используют существующий ModelSettingsStore и ProjectSettingsStore.

MacSettingsStore сохраняет baseline, ввод, последний редактируемый раздел,
commandId и обработанный receipt. `.ok` сохраняет pending до journal;
rejected/offline/stale не уничтожают ввод. Внешние изменения требуют явного
принятия актуального baseline. Применение одного раздела сохраняет другой draft.
⌘↩ отправляет последний редактируемый раздел и после перезапуска. Открытые
sheets сохраняют собственный маршрут основного действия.

Флаги Мака, проекта, пула и модели имеют отдельные строки и scoped команды.
Runner recheck учитывает capabilities/scopes. Снятие cooldown ждёт событие
и не стирает pool/model/runner flags. Время в UI только обновляет подписи;
собственного запуска задач или снятия flags по таймеру нет.

QuotaBars показывают только producer facts: nil, invalid/future/stale значения
остаются неизвестными. Старше 30 минут означает серую реактивную схему.
Authoritative exhausted flag имеет отдельную подпись. Маркеры используют
календарный BillingCycle и пороги остатка, сброс показывает countdown и дату
источника. Без consent опция не отправляется включённой; отзыв подтверждён
событием и сохраняется после restart. Токен не вводится и не хранится в UI.

## Критерии

| Требование FE-20 | Проверка | Результат |
|---|---|---|
| Ceiling/паузы и текущие runs | Typed private wire, process restart; running card в BoardCore | пройдено для Core/private среды |
| Независимые flags/pools/recheck | Flag routes/scopes, simultaneous producer-boundary fixture, isolated cooldown event | пройдено для указанной среды |
| Consent и неизвестные Cm/Om | validation, nil/stale/future/disabled tests, native consent/revoke/restart | клиентская часть пройдена |
| Подтверждение flags и отсутствие локального scheduler | private correlated rate-limit command, существующие limit suites | пройдено для указанной среды |
| Реальный UC-21 producer | GetCurrentPeriodUsage, чтение токена и polling/error status отсутствуют в runtime | **не завершено** |

[Интеграционный пробел](frontend-backend-integration-gaps.md#fe-20-опрос-квоты-cursor)
сохраняет полное требование и необходимые проверки. Fixture quota не закрывает
последний критерий. Отдельная runtime-проверка источника ещё необходима.

## Воспроизведение и оставшаяся приёмка

```sh
KABAN_SCENARIOS=Scenarios/M1 swift test
KABAN_SCENARIOS=Scenarios/M1 swift test --filter KabanBoardCoreTests
xcodebuild -project Kaban.xcodeproj -scheme Kaban \
  -destination 'generic/platform=macOS' -derivedDataPath /tmp/kaban-fe20-app \
  ONLY_ACTIVE_ARCH=YES CODE_SIGNING_ALLOWED=NO build
swiftc tools/seed-mac-settings.swift \
  -I .build/out/Products/Debug -I .build/checkouts/GRDB.swift/Sources/GRDBSQLite \
  .build/out/Products/Debug/KabanProtocol.o .build/out/Products/Debug/KabanKit.o \
  .build/out/Products/Debug/KabanDaemonCore.o .build/out/Products/Debug/KabanTransport.o \
  .build/out/Products/Debug/GRDB.o -lsqlite3 -o /tmp/kaban-fe20-seed
python3 tools/check-mac-settings.py
```

Native NSMenu action подтверждает маршрут ⌘↩, но не физическое нажатие.
Installed helper/XPC, SMAppService, реальные процессы/квота, pointer/keys,
фокус и VoiceOver входят в незавершённую системную приёмку. Полный MVP не принят.

## Повтор после падения CI

На `e279ef5` macOS job упал внутри Swift 6.3.3 IRGen для MacSettingsView,
при генерации actor-isolated setter reabstraction. Локальный Swift 6.4 это
выражение компилировал. На `96fda7f6763003a34f3905b41a7dd574c7b55ebe` два `Binding.set` используют
явные замыкания с вызовом editCeiling/editInterval. Проверки CI не ослаблены.
Причина подтверждается compiler stack; успешность обхода в Swift 6.3.3
проверяется новым CI job, до его завершения не заявлена.

На этом source локальные App build и все 12 native сценариев повторно прошли.
Core не менялся после финальных 211 BoardCore tests на `5c28f6b`.
[Новые результаты](screenshots/fe-20/ci-swift-633/checks.json) и
[манифест кадров](screenshots/fe-20/ci-swift-633/frames.json) сохраняют source.
