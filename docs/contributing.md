# Работа над Kaban

Действует с 5 октября 2026. Kaban — основной проект пользователя.
Работа может менять любой нужный модуль, production-код, существующие тесты,
Package.swift, CI, дизайн и документацию в рамках порученной задачи.
Ограничения временной team2 на занятую зону, новые файлы, ветки team2/ и
исключение Designer отменены. [Прежний документ](archive/2026-10-04/contributing.md) сохранён как история.

## Ветки и PR

- Перед правками проверь ветку, git status и HEAD; перед новой веткой выполни `git fetch origin`
  и выбери актуальную базу `origin/main`. Если fetch недоступен, укажи это в результате.
  Имя ветки и отчёт о PR не подтверждают наличие реализации в checkout.
- Одна задача — отдельная ветка `codex/<задача>` и связный diff. Сохраняй чужие локальные изменения.
- PR направляй в main. Мерж выполняет Артём, пока пользователь явно не поручит мерж агенту.
- Не пушь в чужую ветку и не меняй чужой PR без поручения.
- Размер diff определяется цельностью задачи; старый ориентир team2 в 400 строк не является gate.
- Готовность проверок относится к конкретному HEAD. Зелёная старая ветка не доказывает интеграцию с новым main.
- После принятия инкремента актуализируй базу и статус в `docs/current-state.md` и рабочей очереди.
  Сохраняй SHA/дату исходных проверок в development-отчёте; обновление документов не является новым прогоном.

## Источники и решения

Начни с [current-state](current-state.md) и [AGENTS.md](../AGENTS.md).
Текущее поручение человека приоритетнее документов. Утверждённые изменения
записываются в [decisions-log](decisions-log.md) и соответствующую рабочую спецификацию.
Документация ведётся в Git; [индекс docs](README.md) описывает перенесённые источники Drive.
Не нужно перечитывать отчёты всех ролей перед исправлением одного экрана.

При расхождении кода и требований покажи конкретный сценарий/файл.
Исправление найденного дефекта допускается в порученном объёме: прежний запрет
team2 на production и существующие тесты не применяется. Новый продуктовый
выбор с неоднозначными последствиями обсуждается с пользователем.

## Проверка результата

- Только документы/контекст/оригиналы дизайна: `python3 tools/check-project-context.py` и проверка diff.
- Поведение ядра: содержательные nearby tests и `KABAN_SCENARIOS=Scenarios/M1 swift test`.
- App: отдельный unsigned xcodebuild; реальные действия и настоящее окно, включая визуальную приёмку изменённых экранов.
- Wire/store: совместимость legacy DTO, повтор команд, journal/projection и транзакционные границы.
- Не пропускай новый failing test ради зелёного CI. Старое предписание team2 о skip со ссылкой на issue отменено.
- Пропущенные проверки и проблемы среды указывай явно; не ослабляй assertions ради обхода среды.
- macOS job обязателен: проверяй App build и native smoke на финальном SHA. Успех fixture CI не закрывает installed helper / live Cursor приёмку.

Mock/fake должен соблюдать продуктовые правила. Он не подтверждает работу
Cursor, процессов, durable настроек и XPC. Подпись, регистрация LaunchAgent
и платные CLI-запуски выполняются только в рамках соответствующего поручения.

## Что сообщить

Результат пользовательского сценария, изменённые файлы, выполненные проверки,
границы реализации и следующую необходимую работу. Для UI покажи/укажи снимок
настоящего окна и проверенные состояния. Не заменяй готовность продукта количеством
документов, тестов, кадров галереи или опубликованных PR.
