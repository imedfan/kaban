## Журнал изменений

- **v0.8.25 (2026-10-04, управление проектом передано новой команде):** разрешены вопросы #9/#10/#11/#12 — agent-only `answerHuman`, incident для `.kaban`, отдельная human admission capacity и пустой root diagnostic path. Это уточнения контрактов; реализация scheduler/исполнителя ещё впереди.

- **v0.8.24**: UC-01 — после отказа вызову с `identity` в полях остаётся введённое пользователем; порядок проверки (перенос строки и NUL до обрезки, табы тоже пусто); ссылка §4.1 на арх. v0.11.21.

- **v0.8.23**: UC-01 — уточнение «нашлось только имя / почта» показывается, только когда второе поле в `missing`; при `invalid` его нет.

- **v0.8.22** (под арх. v0.11.21): UC-01 — `identity_required` разбит на первый отказ и отказ вызову с `identity`; уточнения «нашлось только имя / почта»; `invalid` из git-конфига виден уже при первом отказе; пробелы считаются пустым значением; каждое поле ровно в одном виде.

- **v0.8.21**: UC-01 — у подставленных имени и почты пометка «из настроек git».

- **v0.8.20** (под арх. v0.11.20): UC-01 — автор хранится у демона на этом Маке, не в `.kaban/`; строка «Автор коммитов» по `ProjectSummary.identity`; тексты под полями по `CommandError.params` (`missing`, `invalid`), предзаполнение найденным, фокус; подсветка только при отказе вызову с `identity`; подпись галочки «Создать шаблон `.kaban/` и закоммитить».

- **v0.8.19** (под арх. v0.11.19): UC-01 — автор коммитов проекта (`GitIdentity`), альтернатива `identity_required` с текстом и полями в листе «Добавить проект»; UC-19 и §4.1 — команда вне каталога в `extend` read-only стадии даёт только `git_unknown_command` и попадает в «сужено до чтения», `git_readonly_extend` только для известных пишущих команд.

- **v0.8.18**: §4.1 — в тексте `git_readonly_extend` имя стадии в «ёлочках», как у соседних кодов.

- **v0.8.17** (под арх. v0.11.18): UC-19 — четвёртая пометка «сужено до чтения»; явный `deny` read-only стадии показывается так же; пишущий `extend` у read-only стадии — ошибка `git_readonly_extend`. §4.1 — текст для `git_readonly_extend`.

- **v0.8.16** (под арх. v0.11.17): UC-19 — у read-only стадии не-чтение из политики проекта приходит в `denied` с `source: stage`, пометка «сужено до чтения»; «нет в пресете» только для команд вне политики проекта. §1.3 — причина лимита из двух частей, разделитель на вёрстке.

- **v0.8.15** (под арх. v0.11.16): §1.3 — вид причины лимита: на карточке заголовок и уточнение, в ленте строка через « · »; уточнение для пары `returns_to` «<откуда> → <куда>, N из M»; UC-19 — `deny` проекта действует и на read-only стадии.

- **v0.8.14** (под арх. v0.11.14): §1.5 — короткие подписи плиток для семи id (полный текст в поповере), `config` — демон отключает hooks и fsmonitor; §1.3 — причина `run_limit` «Лимит запусков на задачу, N из M»; §1 — список причин лимитов в тех же словах.

- **v0.8.13** (под арх. v0.11.13): §1.3 — причина «Лимит возвратов» для `on_fail`/`on_conflict` («при красном гейте» / «при конфликте») в тех же словах, что подписи полей; §1.5 — `force`: `--force*` по префиксу, любой `clean` без `-n`/`--dry-run`; `config`: запись в `.git/config`, `.git/hooks/`, `.git/info/` клона; §4.1 — подписи `stall`, `wall`, `backoff`, формат длительностей в `{min}`/`{max}`.
