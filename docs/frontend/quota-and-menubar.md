Требования выделены из frontend-plan v0.5.37 без изменения поведения.
Статус реализации — [current-state](../current-state.md); порядок работы — [frontend-plan](../frontend-plan-v0.md).
Имена DTO и команд сверять с `Sources/KabanProtocol/`; числовые ссылки 3.x сохранены из исходного плана.
Предложения фронта остаются предложениями. Макеты и токены — [design](../../design/README.md).

**3.12 Менюбар и уведомления.** `MenuBarExtra(.window)`: значок с числом «ждёт человека» (с пометкой, если поднят флаг Мака), слоты `n/4`, полосы квоты Cm/Om, если опция включена (3.13), список ждущих задач, cooldown с «Снять сейчас», «Cursor недоступен» с «Проверить снова», `pauseAll` / `resumeAll`, «Открыть доску». После закрытия окна приложение живёт в менюбаре (`.accessory`) **(предложение фронта)**. Уведомления (`UserNotifications`, `threadIdentifier` = проект) — на `waiting_human`, включая `review` (по умолчанию включено, выключается в настройках): у `question` «Ответить» с вводом текста → `answerHuman`; инцидент — `.timeSensitive` (FS-6); cooldown — «лимит Cursor, возобновление в 16:40»; `runner_unavailable` — одно уведомление при включении флага, не на каждую задачу (UC-20). События старше 10 минут после догонки собираются в одну сводку **(предложение фронта)**.

**3.13 Квота Cursor (опция «неофициально», по умолчанию выключена).**
- `QuotaBars` в менюбаре и блоке «Этот Мак»: две полосы — **Cm** (модели Cursor, `composer-*`, `autoPercentUsed`) и **Om** (именные модели, `apiPercentUsed`). Полосы Gb нет. У каждой полосы метка прошедшей доли цикла и метка порога; подпись — обратный отсчёт до сброса по `billingCycleEnd` («сброс через 9 д»). Доля цикла считается от `billingCycleStart`; если его нет в ответе (проверяется в спайке 1), начало цикла считается календарно — тот же день месяцем раньше от `billingCycleEnd` (не «минус 30 дней»); метка доли цикла использует этот запасной расчёт. `billingCycleEnd` демон разбирает из строки с миллисекундами эпохи, UI получает `Date`. Исчерпанный пул (`usage_exhausted · cm` / `om`) — полоса заполнена, подпись «исчерпан».
- **Нет данных ≠ 0%.** Если в `quotaUpdated` процент пула `nil` (в том числе когда Cursor ответил `"enabled": false`), полоса — серая заглушка с подписью «нет данных», не пустая и не полная; без метки порога. Нет `billingCycleEnd` — нет отсчёта и метки доли цикла. Если данным больше 30 минут, полосы тоже серые с подписью «нет свежих данных — работает реактивная схема».
- Экран Мака «Квота Cursor»:
  - блок согласия (`setQuotaOptions(enabled, consent, pollInterval, thresholdCm, thresholdOm)`): включается явно, с пометкой «неофициально»; текст объясняет, что токен читается только для чтения (из `state.vscdb` Cursor IDE или токен CLI), живёт только в памяти, не обновляется, а запрос идёт только к `api2.cursor.sh` `GetCurrentPeriodUsage`;
  - интервал опроса: 1 / 5 / 15 / 30 мин или своё значение (перед каждым стартом запуска демон и так берёт данные не старше 60 с);
  - пороги Cm и Om отдельно, по умолчанию 10% (демон закладывает запас на идущие запуски);
  - таблица «модель → пул»: правила по префиксу и исключения (`setModelPoolRule` / `removeModelPoolRule`), свёрнуто по семействам, значок «проверь пул» (`needs_review`) у новых моделей и фильтр по нему, кнопка «Обновить список» (`refreshModelCatalog`).
- Если чтение `state.vscdb` из-под LaunchAgent вызывает системный запрос, базу читает приложение и передаёт демону проценты (арх. §7, спайк 1); тогда в приложении появляется маленький читатель квоты без записи и без хранения токена.
- Om ниже порога при остатке в Cm — встают только стадии на именных моделях; их задачи показывают серую причину на карточке (3.4).
- Пробные запуски после молчаливого выхода без вызовов инструментов (один на модель за раз, не чаще раза в 10 минут; при неизвестной дате сброса — раз в 6 часов) попытку не списывают; карточка в это время в `retry_wait: silent_exit` (3.4).

**Маскот** (`MascotView`; арх. v0.11.21 §2: рисует приложение по `ProjectSummary.mascotSeed`, генератора в `KabanKit` нет). Кит дизайнера — `design/mascots/` (README, `mascot-kit.js`, `ref/MascotKit.swift`, `test-vectors.json`): 30 маскотов — одиночные кодпоинты эмодзи (порядок в списке входит в спецификацию), 8 бесцветных фактур левого края шириной 6 pt (SVG для светлой и тёмной темы). Правило (спека v0.8.22 UC-16, F18): `h` = FNV-1a 64 по UTF-8 байтам `ProjectSummary.mascotSeed`, маскот = `h % 30`, фактура = `(h / 30) % 8`; сид по умолчанию — id проекта (арх. v0.11.21). Совпадения на доске: проекты обходятся в порядке добавления (`BoardSet.addedOrder`), у более позднего проекта с той же парой фактура сдвигается на +1, +2… по модулю 8; это только отображение, нигде не сохраняется; маскот не меняется. Пикер (UC-16): только 30 маскотов кита, без свободного эмодзи и SF Symbol; клиент ищет наименьшее k ≥ 1, при котором `pick("<projectId>#k")` даёт выбранную пару, и шлёт `setMascot(projectId, seed)`. Реализовано в PR #6, коммит `30d6734`: `MascotKit` в `KabanBoardCore` совпадает с эталоном дизайнера, тесты на векторах кита, CI зелёный; `mascotSeed` уже есть в базе протокола, `TODO(protocol)` не нужен. `EdgeTextureView` (набросок SwiftUI `Canvas` из кита) соберём на Маке Артёма в понедельник. `.breathe` — спит, `.pulse` — агенты работают, `.wiggle` — ждёт человека, `.bounce` — однократно на Done; «тревожится» при инциденте (UC-16.3) готового эффекта не имеет — предлагаю красный бейдж с `.pulse` и красное кольцо, как на макете **(предложение фронта)**. Приоритет: тревога > ждёт > работает > Done > спит. Анимация только в сайдбаре и шапке дорожки, на карточке статичная наклейка. С Reduce Motion всё статично. Эмодзи анимируются через `keyframeAnimator` (FS-5).

Попытка не спишется»; вперёд — запрещено, кроме Backlog → первая стадия при наличии критериев приёмки; между проектами — нельзя. Перетаскивание самих проектов — в 3.10.
