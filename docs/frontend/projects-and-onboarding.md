Требования выделены из frontend-plan v0.5.37 без изменения поведения.
Статус реализации — [current-state](../current-state.md); порядок работы — [frontend-plan](../frontend-plan-v0.md).
Имена DTO и команд сверять с `Sources/KabanProtocol/`; числовые ссылки 3.x сохранены из исходного плана.
Предложения фронта остаются предложениями. Макеты и токены — [design](../../design/README.md).

**3.10 Добавление проекта и набор проектов на доске** (журнал решений от 4 октября, арх. v0.11.1 §11; автор коммитов — арх. v0.11.21 §5, §8.2, спека v0.8.22 UC-01).
- `AddProjectFlow`: `fileImporter` → `addProject(path, createTemplate, identity?)` (первый вызов — без `identity`) с галочкой «Создать шаблон `.kaban/` и закоммитить» (включена; подпись по спеке v0.8.22 UC-01, взята из макета 06) → ветка (`listBranches`) → гейты (`detectGates`, можно править) → `checkEnvironment`. Чистая копия не нужна. «Не git-репозиторий» — ошибка в листе. Галочку шаблона сняли — проект добавлен с флагом `unavailable: no_pipeline`. `cursor-agent` не готов — проект добавлен, над доской баннер `runner_unavailable` (UC-20). Добавленный проект сразу появляется на доске последней дорожкой.
- **Автор коммитов** (`GitIdentity { name, email }`, протокольный патч ceabd81d…; арх. v0.11.21 §8.2; спека v0.8.22 UC-01; макет `06-add-project-identity`, светлая и тёмная тема, сверен со спекой v0.8.23). Без `identity` демон один раз читает `user.name` / `user.email` обычным git пользователя в этом репозитории (конфиг репозитория, глобальный и системный); клиент git сам не читает и автора не угадывает. Правила демона (арх. v0.11.21 §8.2): имя и почта обрезаются по краям, значение из одних пробелов — `missing`; перенос строки и NUL отклоняются (`invalid`), в том числе в значении из git-конфига при первом вызове без `identity`; явный `identity` побеждает, пустое поле в нём на репозиторий не откатывается. Если автора нет нигде, имя / почта пустые или недопустимы, `addProject` отвечает `CommandError` с кодом `identity_required` (`CommandError.identityRequiredCode`) и **проект не создаётся** (`projectAdded` нет, на доске ничего не появляется). Детали — в `CommandError.params: [String: String]` (без поля — `[:]`, как у `ValidationIssue`): `missing` = `name` | `email` | `name,email`, `invalid` с тем же форматом, `name` / `email` — найденные значения. Каждое поле попадает ровно в одно место — `missing`, `invalid` или найденные; отклонённое значение не возвращается, поэтому поле из `invalid` пустое; порядок в списках — `name`, `email` (арх. v0.11.21 §8.2, патч). Лист остаётся открытым с той же папкой и галочкой, показывает общий текст спеки «Не задан автор коммитов: укажите имя и почту», открывает поля «Имя» и «Почта» и по «Добавить» повторяет `addProject(path, createTemplate, identity)`. Две ветки по спеке v0.8.22 UC-01:
  - **Первый отказ** (вызов без `identity`). Найденные `params.name` / `params.email` подставляются с пометкой «из настроек git» (они могут прийти из конфига репозитория, глобального или системного); фокус — в первое поле из `missing` или `invalid` (порядок «Имя», «Почта»). Подсветки у полей из `missing` нет. Под общим текстом уточнение: нашлось только имя → «В настройках git нашлось только имя, почты нет»; нашлась только почта → «В настройках git нашлась только почта, имени нет»; ничего не нашлось → без уточнения; уточнение показываем, **только когда второе поле в `missing`**, при `invalid` второго поля его нет — хватает текста под полем (спека v0.8.23 UC-01). Поле из `invalid` пустое, и текст под ним виден сразу, без обводки: «Имя в настройках git содержит служебные символы, укажите вручную» или «Почта в настройках git содержит служебные символы, укажите вручную».
  - **Отказ вызову с `identity`.** Поля из `missing` и `invalid` получают оранжевую обводку ошибки (как ошибки полей в 3.8, не красную) и текст под полем: `missing` — «Укажите имя» / «Укажите почту»; `invalid` — «Имя должно быть в одну строку, без служебных символов» / «Почта должна быть в одну строку, без служебных символов» (перенос строки или NUL); тексты первого отказа заменяются этими; остальные поля не подсвечиваются. В полях остаётся то, что ввёл пользователь (спека v0.8.24 UC-01).
  - **Ключей нет** (старый демон, `params = [:]`): «только общий текст, оба поля без подсветки»; поля открыты и пусты. Клиент сам пустоту и символы не проверяет и подсветку по отправленному не выводит — только по `params` демона.
  - Автор сохраняется у демона на этом Маке и меняется в настройках проекта (`setProjectIdentity`, 3.9). У зарегистрированного проекта автор есть всегда, поэтому `identity_required` на запуске не появляется: отдельного статуса или причины на карточке для него нет (арх. v0.11.21 §8.2, спека v0.8.22 UC-01).
- Переключателя «Один / Несколько / Все» нет, `ProjectScopePicker` убран целиком. Проект попадает на доску перетаскиванием из списка проектов в сайдбаре в область канбана; тем же перетаскиванием (за `LaneHeader`) меняется порядок дорожек.
- Drag-and-drop проектов: `ProjectDragItem: Transferable` с `projectId` (свой UTType `app.kaban.project-ref`, отдельно от `app.kaban.task-ref`, чтобы карточку нельзя было бросить между дорожками) **(UTType — предложение фронта)**; зоны сброса между дорожками, перед первой и после последней; индикатор вставки — линия между дорожками; проект, уже стоящий на доске, при сбросе переезжает, а не дублируется. Итог — `BoardSetStore.add(at:)` / `move`.
- Крестик «Убрать с доски» в `LaneHeader` справа, сразу после кнопки настроек: `BoardSetStore.remove`. Только скрывает дорожку: проект не удаляется и не ставится на паузу, задачи продолжают выполняться, команд демону нет.
- Пустая доска (в наборе ни одного проекта) — `EmptyBoardView` с подсказкой «Перетащите проект сюда»; вся область — зона сброса.
- Скрытый проект в сайдбаре остаётся со значками `waiting_human` и инцидента; раздел «Ждут человека», «Инциденты», менюбар и уведомления охватывают все проекты.
- Доступность: перетаскивание дублируется пунктами контекстного меню проекта в сайдбаре «Показать на доске» / «Скрыть с доски» (VoiceOver, клавиатура). ⌘1–⌘9 прокручивают доску к N-й дорожке и ставят на неё фокус; ⌘⌥← / ⌘⌥→ сдвигают дорожку в фокусе без мыши (`BoardSetStore.move`). Всё это есть пунктами меню «Вид».

**3.11 Онбординг** (первый запуск и поломка окружения):
1. `SMAppService.agent(...).register()`; при `.requiresApproval` кнопка «Открыть Объекты входа», статус перепроверяется при возврате в приложение, потом XPC-ping.
2. `SMAppService.mainApp` — автозапуск менюбар-аппки.
3. `requestAuthorization` для уведомлений, шаг можно пропустить.
4. `checkEnvironment`: путь и версия `cursor-agent`, `authOK`, git, `sandboxOK`; путь можно указать вручную; логин — инструкция «`cursor-agent login` в Терминале» и «Проверить снова» (`recheck(.runner)`).
5. Первый проект.
