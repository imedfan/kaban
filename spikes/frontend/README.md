# Спайки фронтенда FS-1…FS-9

Одноразовое приложение `KabanSpikes` для одного прогона на `mbp` (macOS 26, Xcode 26). Это не каркас `Kaban.app` и не контракт демона: типы свои, модули `KabanProtocol`, `KabanKit` и `KabanBoardCore` не импортируются. Linux CI собирает только SwiftPM-пакет в корне; этот каталог в пакет не входит.

**Здесь ничего не собиралось и не запускалось.** В среде, где писался код, нет macOS и Xcode. `run.sh` на Linux не проверялся. Ниже честно перечислено, какие вызовы сверены с документацией и чужим кодом под macOS 26, а какие могут не собраться с первого раза.

## Что открыть в понедельник

1. Выполнить команды из раздела «Команды».
2. Пройти FS-1…FS-9 в приложении, для каждого записать вердикт в [`RESULTS.md`](RESULTS.md).
3. Сырые логи и скриншоты сложить в [`results/`](results/) (каталог в git не коммитится, кроме `.gitkeep`).
4. В конце снять регистрацию агента, чтобы LaunchAgent спайка не остался в Объектах входа.

Журнал, который пишет само приложение: `~/Library/Logs/KabanSpikes/session.log`. В Console.app фильтр по subsystem `app.kaban.spikes`. Точки Instruments — category `PointsOfInterest`.

## Чего в этом прогоне нет

Код не компилировался. Сборка на Маке — первая проверка. Если `xcodebuild` падает, не чините наугад весь проект: в конце есть раздел «Если не собирается» с конкретными местами.

Не проверено вообще:

- генерация `project.yml` текущим XcodeGen и точный `subpath` копирования plist;
- любой вызов `XPCListener` / `XPCSession` (формы взяты из приложений 2026 года на macOS 26, но этот таргет не линковался);
- `.glassEffect` / `GlassEffectContainer`;
- `.symbolEffect(.breathe/.pulse/.wiggle/.bounce)` в той комбинации, что в FS-5;
- `SMAppService` вместе с вложенным LaunchAgent именно этой раскладки бандла;
- что `CREATE_INFOPLIST_SECTION_IN_BINARY` даёт агенту bundle id, достаточный для `UNUserNotificationCenter`;
- bundle id Cursor `com.todesktop.230313mzl4w4u92`;
- `task_info(TASK_VM_INFO)` / поле `phys_footprint` против SDK 26 (обычный способ, но не сверенный здесь);
- флаг `./run.sh --developer-id` (ручная подпись Developer ID).

`PipelineYamlEditor` тоже не гонялся здесь. `./run.sh` компилирует его через `swiftc` и проверяет фикстуру до `xcodebuild`. Это единственная автоматическая проверка, и она выполнится уже на Маке.

## Согласование с бэкендом

Нумерация бэкенда — архитектура §14. Скрипты бэкенда живут в `spikes/backend/` и этим PR не трогаются.

| Фронт | Бэкенд | Как не мешать друг другу |
|---|---|---|
| FS-1 | спайк 3, `SMAppService` + Mach + `XPCSession` | У спайка свой Mach `app.kaban.spikes.agent` и свой plist. Запускайте заглушку и бэкенд-спайк разными приложениями. Не подменяйте бинарник и не вешайте оба на одно имя. |
| FS-6 | спайк 4, уведомления из агента в бандле | Кнопки «из агента» шлют `postNotification` в заглушку и пишут дословный ответ в журнал. Это вход для спайка 4, не его замена. Вердикт «можно ли из агента» ставит бэкенд; фронт фиксирует, что получилось у заглушки. |

Остальные FS от бэкенда не зависят.

## До прогона, пока Мак ещё в сети

Если в понедельник сети не будет, это нужно сделать заранее:

- [ ] macOS 26.
- [ ] Xcode 26, и `xcode-select` смотрит на него, не на Command Line Tools: `xcodebuild -version` печатает `Xcode 26…`.
- [ ] Сертификат Apple Development в связке ключей (Xcode → Settings → Accounts). Team ID из 10 символов.
- [ ] `brew install xcodegen`. Нужен XcodeGen, который принимает `deploymentTarget: macOS: "26.0"`.
- [ ] Для отдельного прогона FS-6 под Developer ID — сертификат Developer ID Application. Нотаризация и timestamp сервера Apple без сети не пройдут; этот прогон можно пропустить и так и записать.
- [ ] Cursor установлен, если будете смотреть FS-9. Команда `cursor` в `PATH` желательна.
- [ ] Узнать bundle id, если кандидат ниже не подойдёт: `osascript -e 'id of app "Cursor"'`.

Ad-hoc (`codesign --sign -`) для FS-1, FS-6 и FS-7 не годится: launchd отклоняет такой LaunchAgent (Launch Constraint). Обычный `./run.sh` подписывает Apple Development.

## Команды, по порядку

Из корня репозитория:

```bash
cd spikes/frontend
security find-identity -v -p codesigning
export DEVELOPMENT_TEAM=XXXXXXXXXX
./run.sh
```

Скрипт по очереди: проверяет, что Xcode на месте; пишет `Config/Signing.xcconfig` (файл в git не коммитится); гоняет yaml self-check; вызывает `xcodegen generate`; собирает Debug в `build/DerivedData`; проверяет, что в `.app` лежат агент и plist; печатает `codesign -dv` и путь, откуда открывать.

Дальше для FS-1 и FS-7 — стабильный путь, не DerivedData:

```bash
mkdir -p "$HOME/Applications"
ditto "build/DerivedData/Build/Products/Debug/KabanSpikes.app" "$HOME/Applications/KabanSpikes.app"
open "$HOME/Applications/KabanSpikes.app"
```

FS-2…FS-5, FS-8 и FS-9 можно открыть и из DerivedData: `open` на тот `.app`, который напечатал скрипт. FS-6 (кроме вопроса про Developer ID) тоже.

Повторно открыть последнюю сборку: `./run.sh --open`. Только перегенерировать проект, без `xcodebuild`: `./run.sh --generate-only`.

Отдельный прогон подписи Developer ID (FS-6, повышенная важность), когда сертификат есть и сеть для timestamp есть:

```bash
export DEVELOPMENT_TEAM=XXXXXXXXXX
export CODE_SIGN_IDENTITY="Developer ID Application: Имя (XXXXXXXXXX)"
./run.sh --developer-id
```

Это Release и `CODE_SIGN_STYLE = Manual`. Набор флагов не проверялся. Если Gatekeeper или timestamp мешают, запишите текст диалога и не считайте прогон выполненным.

Сгенерированный `KabanSpikes.xcodeproj` в git не кладём.

## Общее для всех экранов

Слева список спайков. Снизу полоса: `phys_footprint` (как Activity Monitor, если `task_info` сработал) и CPU процесса в процентах, может быть больше 100 на нескольких ядрах. Окно можно закрыть: процесс не завершается (`applicationShouldTerminateAfterLastWindowClosed` → false). Менюбар «Kaban Spikes» остаётся, пока не нажмёте «Завершить».

## FS-1. XPCSession и SMAppService

Заглушка `KabanSpikeAgent` в `Contents/MacOS`, plist в `Contents/Library/LaunchAgents`. Имя Mach-сервиса `app.kaban.spikes.agent`. Если у бинарника есть Team ID, слушатель и клиент требуют same-team; без Team ID требование снимается и в журнал пишется предупреждение — такой прогон всё равно не зачёт.

Экран показывает, на месте ли бинарник и plist, статус `SMAppService`, pid, boot id, seq и журнал.

Шаги:

1. Открыть копию из `~/Applications`.
2. Убедиться, что оба файла агента зелёные и Team ID не «нет».
3. «Зарегистрировать». Если статус `requiresApproval` — «Объекты входа», включить тумблер, вернуться в приложение (статус перечитывается раз в секунду и при активации).
4. «Подключиться». В журнале `pong` с pid, boot id и миллисекундами.
5. «Убить демон». Ожидание: строка отмены сессии, затем паузы 0.5 → 1 → 2 → 5 с, новый pid и **новый boot id**, `resyncRequired` (журнал заглушки живёт в памяти процесса).
6. «Событие», затем «Обрезать журнал». Следующий цикл снова должен дать `resyncRequired`.
7. Включить и выключить «Автопереподключение» и убедиться, что без него после kill повтор сам не идёт.

Зачёт, если все пункты ниже верны:

- оба бинарника подписаны одним Team ID, в `codesign -dv` нет ad-hoc;
- после одобрения статус `enabled`;
- ping возвращает pid и boot id, время круга записано;
- после SIGTERM есть отмена, backoff и новый boot id;
- и убийство, и обрезка журнала дают `resyncRequired`.

Что записать: статус до и после одобрения, время ping, оба boot id, строки `resyncRequired`, путь к скриншоту журнала.

Если не взлетит: **нет основы клиента** (план, раздел 6). Не собирайте обходной транспорт.

Рядом в тот же день — бэкенд-спайк 3, отдельным процессом.

## FS-2. Дорожки

Синтетика ровно 10 дорожек × 7 столбцов × 50 карточек (3500). Внешний `LazyVStack(pinnedViews: .sectionHeaders)`, внутри каждой дорожки свой горизонтальный `ScrollView`. `GlassEffectContainer` один на дорожку, `.glassEffect` только на шапках столбцов. Карточки сплошные, радиус 10. Шапка дорожки без стекла, чтобы закрепление было видно. В углу счётчик fps (`TimelineView(.animation)`). «Материализовано» считает карточки, у которых вызвался `onAppear`.

Шаги:

1. Дождаться генерации. На экране должно быть `10 × 7 × 50 = 3500`.
2. Прокрутить внешний список: шапки дорожек остаются закреплёнными.
3. Прокрутить столбцы одной дорожки по горизонтали и карточки внутри столбца по вертикали. Соседняя дорожка не должна ехать вместе с ней.
4. Сбросить счётчик материализации, не трогая скролл две секунды, записать число. Потом прокрутить и записать, растёт ли оно.
5. Поводить скролл и смотреть fps. Параллельно можно снять Instruments: Animation Hitches, Time Profiler, Points of Interest (`FS2.Generate`, `FS2.BoardAppear`).

Зачёт:

- шапки закреплены, горизонтальный скролл у каждой дорожки свой;
- стекло видно на шапках столбцов и не на карточках (скриншот);
- при прокрутке fps большую часть времени ≥ 50, пляжного мяча нет;
- `phys_footprint` записан, свопа нет.

Ориентир провала по памяти: стабильно выше 1.5 ГБ на эту синтетику или своп. Число материализованных карточек без прокрутки запишите отдельно: если сразу 3500, лень не сработала. Сам по себе это не провал, если кадры и память в норме, но это аргумент в пользу другой раскладки.

Если не взлетит: **другая раскладка дорожек**.

Что записать: fps, footprint, сколько карточек появилось без прокрутки, скриншот стекла и закреплённой шапки.

## FS-3. Drag

Маленькая доска, не 3500 карточек. Свои UTType: `app.kaban.spike.task-ref` и `app.kaban.spike.project-ref` (не боевые `app.kaban.task-ref` / `app.kaban.project-ref`).

Правила карточки в этом спайке: чужой проект — нельзя; вперёд — нельзя, кроме Backlog → Dev при наличии критериев; назад — можно (в журнале `allowNeedsConfirm`); тот же столбец — нет. Ворота (`GateStrip`) принимаются отдельно, даже с более ранней стадии: проверяется сама зона, не боевое правило «вперёд нельзя». Свёрнутый столбец Test у проекта Alpha.

Подсветка: зелёный — можно, оранжевый — назад, красный — нельзя, серый — тот же столбец. Индикатор вставки проекта — полоска между дорожками, пока тянете проект.

Шаги:

1. Карточку без критериев из Backlog тянуть в Dev — красная цель, drop не проходит.
2. Карточку с критериями из Backlog в Dev — проходит.
3. Карточку из Review назад в свёрнутый Test — столбец принимает и разворачивается.
4. Любую карточку того же проекта на полоску «ворота» — в журнале `drop на GateStrip`.
5. Карточку на другую дорожку — отказ.
6. «Гамма» из списка слева на доску, в промежуток между дорожками. Полоска видна. Повторный сброс той же Гаммы не добавляет вторую копию, а переносит.
7. Потянуть дорожку за шапку и сменить порядок.
8. Если drag молчит, выполнить те же действия из меню «Переместить в» / «Показать на доске» и пометить, что сработал только запасной путь.

Зачёт: пункты 1–7 происходят перетаскиванием, подсветка совпадает с правилом.

Если не взлетит: **только меню «Переместить в» / «Показать на доске»**. Оба пункта в спайке уже есть.

Что записать: какие жесты прошли, скриншот красной и зелёной подсветки и полоски вставки. Если drop не срабатывает совсем, приложите `plutil -p` на `Info.plist` собранного приложения (секция `UTExportedTypeDeclarations`).

## FS-4. Живой лог

`NSTextView(usingTextLayoutManager:)` — TextKit 2, если `textLayoutManager != nil` (на экране будет «TextKit 2»). Только чтение, `usesFindBar`. 100 000 событий дописываются батчами по 400 строк. Интервал батча — слайдер 100–250 мс, по умолчанию 150. В поле не больше 50 000 строк: при стриме старые строки выкидываются сверху, «Загрузить ранее» добавляет 2000 строк в начало и при лимите срезает хвост. Автопрокрутка только если вид у нижнего края; прокрутка вверх её выключает. Батч оборачивается в `beginEditing` / `endEditing`, signpost `FS4.Batch` и `FS4.LoadEarlier`.

Шаги:

1. «Пустить 100k». Дождаться конца (около полуминуты при 150 мс).
2. Убедиться, что подпись движка — TextKit 2, событий 100000, строк в поле не больше 50000.
3. Пока идёт стрим, прокрутить вверх: хвост не должен утаскивать вид вниз. Включить «следить за концом» обратно и нажать не нужно — тумблер сам снимется; включите снова и проверьте, что вид возвращается к концу на следующем батче (если стрим ещё идёт) или остаётся, куда вы его поставили.
4. ⌘F открывает панель поиска, не системный диалог.
5. «Загрузить ранее» увеличивает диапазон с меньшего seq.
6. В Allocations посмотреть устойчивый объём `NSTextStorage` после того, как стрим кончился.

Зачёт: TextKit 2, все 100k событий дописаны батчами в диапазоне 100–250 мс, в поле ≤ ~50k строк, автопрокрутка ведёт себя как выше, ⌘F открывает find bar, нет пляжного мяча дольше секунды, footprint записан.

Ориентир провала по памяти: после усечения до 50k строк footprint стабильно выше 800 МБ.

Если не взлетит: **виртуализированный список**.

Что записать: движок, длительность батча из подписи на экране, число строк, footprint, открылся ли ⌘F.

## FS-5. Маскоты

N от 1 до 40. На каждого — SF Symbol и, если тумблер включён, эмодзи. Режимы: breathe (спит), pulse (работает), wiggle (ждёт), bounce по кнопке Done. Эмодзи крутится через `keyframeAnimator`, когда режим «ждёт». При Reduce Motion (Системные настройки → Универсальный доступ → Дисплей) символы не активны и эмодзи статичны.

«Замер 20 с» раз в секунду считает CPU процесса. В это время не двигайте мышь и не печатайте. Снимите два замера: N=1 и N=10, оба с эмодзи, режим «работает» (pulse) и отдельно «ждёт» (wiggle + keyframe). В Instruments — Energy Log и Time Profiler.

Зачёт:

- при включённом Reduce Motion и символы, и эмодзи статичны;
- при N=10, эмодзи включены, 20 с простоя, среднее CPU процесса **< 20%** и вентиляторы не раскручиваются.

Провал, если среднее ≥ 20% или Energy Log показывает непрерывную анимацию в простое. Тогда запасной путь: **анимация только по событию**.

Что записать: оба замера (среднее и макс с экрана), режим, был ли Reduce Motion, ощущение по вентиляторам.

НЕ ПРОВЕРЕНО: модификатор `.symbolEffect(.wiggle, options: .repeating, isActive:)`. Замена одной строкой — в комментарии на экране FS-5 и в разделе ниже.

## FS-6. Уведомления

Категория вопроса с `UNTextInputNotificationAction`, инцидент с `interruptionLevel = .timeSensitive`. Делегат показывает баннер, даже если приложение на переднем плане. Ответ пишется на экран.

Шаги обычной подписи (Apple Development):

1. «Разрешить уведомления» и согласиться в системном диалоге.
2. «Вопрос с полем ответа». В баннере ввести текст. Он появляется в строке «Текст ответа».
3. Закрыть окно. Из менюбара снова отправить вопрос, ответить. Открыть окно: текст на месте, процесс не завершался.
4. «Инцидент timeSensitive» — записать, как выглядит баннер. Это ещё не ответ на вопрос плана про Developer ID.

Шаги Developer ID (отдельная сборка `./run.sh --developer-id`), если сертификат и сеть есть:

5. Включить «Не беспокоить» или Focus.
6. Прислать инцидент. Зачёт этой части — баннер всё равно показан. Если система понизила важность, это провал только этой части.

Кнопки «из агента» не входят в зачёт FS-6. Запишите ответ дословно: это данные для бэкенд-спайка 4.

Зачёт FS-6: разрешение получено, текстовый ответ доходит и при открытом окне, и после его закрытия.

Если не доходит ответ или уведомление при закрытом окне: провал FS-6, запасной путь плана на этот случай не сформулирован отдельно от timeSensitive — запишите факт.

Если под Developer ID timeSensitive не повышенная: **инцидент без повышенной важности**. Development-подписью этот пункт не закрывается. Нет сертификата или сети — в RESULTS напишите «не проверялось», не подменяйте результатом Development.

Шаги:

1. Запуск из `~/Applications/KabanSpikes.app`, не из DerivedData.
2. «Зарегистрировать», одобрить в Объектах входа, дождаться `enabled`. Скриншот тумблера.
3. Выйти из приложения («Завершить» в менюбаре).
4. `ditto "$HOME/Applications/KabanSpikes.app" "$HOME/Desktop/KabanSpikes.app"` и `open` с Рабочего стола.

## FS-8. pipeline.yaml

Фикстура `Resources/pipeline.yaml` копируется в бандл. В ней шапочные комментарии, комментарий с числом 12, встроенный комментарий на строке `max_runs_per_task`, блок `|` со словами `composer-2` и `12`, порядок ключей `version`, `board`, `stages`.

«Эталон 13 / opus-4.5» делает две точечные замены: `board.max_runs_per_task` и `stages[1].model` (это стадия dev). Рядом — наивная перезапись: комментарии выбрасываются, ключи сортируются. Это стенд вместо Yams, саму библиотеку не подключали.

`./run.sh` до сборки гоняет тот же эталон через `swiftc -D SPIKE_YAML_MAIN`. Если эта команда упала, в приложение можно не идти: спайк уже красный, текст ошибок — в выводе скрипта.

Зачёт эталона:

- точечная правка меняет только два значения, строка `max_runs_per_task` сохраняет хвост `# не трогать этот комментарий`;
- все строки-комментарии на месте, число строк то же;
- блок `|` цел, включая `composer-2` внутри него;
- порядок `version`, `board`, `stages` тот же;
- наивная перезапись комментарии теряет (так и задумано, это не провал).

Кнопка «Применить поля» проверяет только сохранность строк-комментариев для ваших значений. Значение с `#` или переводом строки редактор отвергает.

Парсер — подмножество: отступы пробелами, скаляр на той же строке, что ключ, списки `- key:`, блоки `|` / `>`. Якоря, flow (`{…}`, `[…]`) и многострочные ключи не обещаются. Если боевой `pipeline.yaml` на таком конструкте сломается, это провал подхода, даже если эталон зелёный: вставьте кусок в фикстуру и запишите, на чём.

Если не взлетит: **писать только свои поля, правка текста точечно**. Если ломается уже точечная правка эталона, зафиксируйте конструкцию, из-за которой, и не чините это вторым сериализатором в том же прогоне.

osascript -e 'id of app "Cursor"'

## Если не собирается

Меняйте только указанное место и снова `./run.sh`.

| Симптом | Где |
|---|---|
| XcodeGen не знает macOS 26 | Обновить XcodeGen. Иначе в `project.yml` оставить `MACOSX_DEPLOYMENT_TARGET = 26.0` в `settings` и временно поставить `deploymentTarget` на ту версию, которую примет генератор, не опуская SDK Xcode. |
| Нет `Contents/MacOS/KabanSpikeAgent` | Блок `dependencies` → `embed` / `destination: executables` в `project.yml`. |
| Plist не в `Contents/Library/LaunchAgents`, а глубже | `subpath` у copy files: поменять `Contents/Library/LaunchAgents` на `Library/LaunchAgents`. |
| Нет `init(service:)` / `requirement:` у `XPCListener` | `Agent/AgentMain.swift`, функция `makeListener`. Рабочая форма, на которую опирались: `try XPCListener(service: name, requirement: .isFromSameTeam()) { request in request.accept { message in … } }`. |
| Нет `XPCSession(machService:options:)` | `App/Support/SpikeAgentClient.swift`, `ensureSession`. Полная форма из документации: `init(machService:targetQueue:options:incomingMessageHandler:cancellationHandler:)`. Хвост-замыкание в короткой форме — отмена, по аналогии с `xpcService:` в Thaw. |
| Нет `XPCRichError` или другой `Result` у `send` | Там же, вызов `current.send`. Оставьте тот `Result`, который покажет компилятор, разбор `message.decode(as: SpikeReply.self)` не трогайте. |
| Нет `.glassEffect` / `GlassEffectContainer` | `FS2LanesView.swift`. Не подменяйте на `.ultraThinMaterial`: спайк как раз про стекло. Если SDK не 26, остановите прогон. |
| Не собирается `.wiggle` | `FS5MascotView.swift`, строка с комментарием на экране: `.symbolEffect(.wiggle, options: .repeat(.continuous), value: mode)`. |
| Нет `openSystemSettingsLoginItems` | `SpikeAgentClient.openLoginItems`. Запасной вызов тот же, что в документации ServiceManagement; другого API в спайке нет. |
| `task_info` / `TASK_VM_INFO` | `App/Support/ProcessStats.swift`. Функцию `physicalFootprint` можно заставить возвращать `nil`: полоса покажет `n/a`, спайки от этого не блокируются. CPU через `getrusage` оставьте. |
| Drag начинается, drop не приходит | В собранном приложении нет `UTExportedTypeDeclarations`. Источник — `App/InfoAdditions.plist`. |
