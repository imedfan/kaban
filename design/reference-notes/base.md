## Ключевые решения (кратко)

1. **Четыре уровня веса карточки**: спокойно (queued, paused, done, cancelled) → активно (running, gating, retry_wait: цветной статус и полоска прогресса) → внимание (waiting_human, blocked: подложка статус-строки и рамка) → тревога (инцидент: красная заливка, свечение, уведомление). Так `retry_wait`, «ждёт Cursor» и `waiting_human` различаются с первого взгляда (вопрос архитектора).
2. **Цвет = статус, проект = маскот + фактура края** (сплошная, полоски, точки, штрихи). Цвет проекта не используется.
3. **Статус всегда в статус-строке** внизу карточки; бейджи только для того, что статусом не является: git-разрешение → возвраты/конфликт → пересечение файлов → модель; видно максимум 2.
4. **Флаги планировщика — не на карточках**: Мак (`rate_limited`, `runner_unavailable`, пауза) — баннер над доской; проект (`paused`, `intake_paused`, `unavailable`, `merge_blocked`) — плашка в шапке дорожки, с «Проверить снова», где применимо. Задачи под флагом остаются `queued`.
5. **Конфликт — это возврат**: бейдж «возврат: конфликт 1/2» на `queued`-карточке, затем Human Review с пометкой «после конфликта» и отдельным блоком изменённых файлов.
6. **Вес событий в ленте**: отказ git — тихая серая запись с кнопками только для человека; жёсткое правило — с замком, без кнопок; инцидент — закреплённый красный блок над лентой с тем, что откатано и когда открыт, и подсказкой «Инцидент закроется, когда вы выберете действие по задаче» (отдельной кнопки «Разобрать» нет).
7. **Git-настройки стадии в одном месте**: пресет проекта сверху, таблица «Проект / Стадия / Итог», переопределения стадии — попап «Наследует / Разрешено / Запрещено / По условию», справа итоговая политика стадии и YAML-превью; жёсткие правила — заблокированные строки.
8. **Стекло только на «хроме»** (сайдбар, тулбар, панель задачи) — контент (карточки) непрозрачный, чтобы плотный текст читался.

## Открытые вопросы к команде

1. ~~Состав пресетов~~ — утверждён: «Строгий» — агент только читает (`status diff log show`), коммит делает демон после зелёных гейтов (сообщение из `summary` в `complete_stage`, всё изменённое в клоне, фильтр только `.gitignore`); «Стандартный» — чтение + `add`/`commit` в ветке задачи; «Свободный» — стандартный + `stash`, `rebase`, `reset` (в т.ч. `--hard`) только в своей ветке задачи. Жёсткие правила — во всех трёх.
2. Нужен ли «Ждут человека» в сайдбаре с учётом `review` или без (сейчас считает все `waiting_human`)?
3. Где жить «Разрешениям git» задачи: отдельная вкладка в панели (как в макете) или только бейдж + лента?
4. Анимация маскота (спит/работает/машет/радуется/тревожится) — нужен отдельный motion-спек; в PNG состояние показано точкой-индикатором.
5. Компактный вид «по типу стадии» и столбец «ждёт человека» пока только упомянуты (переключатель в тулбаре, чип стадии на карточке) — отрисовать в v0.2.
6. Окно настроек: отдельное окно (как в макете) или sheet поверх доски?
7. Порядок и лимит бейджей (максимум 2 + «+N») — подтвердить на реальных данных.
